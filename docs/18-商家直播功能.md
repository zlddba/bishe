# 商家直播功能（2026-11-05）

> 一句话：**机构开播 → 用户观看 → 平台审核**。
> 音视频走自建 SRS（RTMP 推 / HLS·HTTP-FLV 拉）。**开播由 App/桌面端自己采集摄像头与麦克风直接推流**
> （Android：RootEncoder；桌面：JavaCV/FFmpeg），不依赖 OBS；后端负责直播间、在线人数、弹幕与封禁。

---

## 一、能力矩阵

| 端 | 开播 | 观看 | 弹幕 | 审核 / 封禁 |
|---|---|---|---|---|
| 机构 App / 桌面端 | ✅ 软件内直接开播（摄像头 + 麦克风 → RTMP） | ✅ 内嵌播放器看别人的直播 | ✅ | — |
| 小程序（uniapp） | —（只读） | 接口已通，页面由小程序端自行接入 | 接口已通 | — |
| 管理后台 | — | ✅ 列表 / 详情 / 拉流地址 | ✅ 隐藏违规弹幕 | ✅ 强制下播 / 封禁机构 / 解封 |

> 说明：App/桌面端「开播」= 创建直播间拿到 `push_url`，随后**由客户端自己采集摄像头 + 麦克风做
> H.264/AAC 编码并推 RTMP**（Android 用 RootEncoder 的 `RtmpCamera2`，桌面用 JavaCV/FFmpeg）。
> 外部推流工具（OBS 等）只是备选，不是必需。

## 二、架构

```
机构 App/桌面端（摄像头+麦克风） --RTMP:9201--> SRS --HLS:9202--> 小程序 <video>
                                                     --HTTP-FLV:9202--> App / 桌面（内嵌播放器）
后端 :9200  ← 直播间/弹幕/封禁 HTTP API
```

- **推流凭证** = `live_rooms.stream_key`（12 字节随机 hex）。只有开播接口和后台详情会下发它；
  观看端拿到的 `LiveRoom` 里 `stream_key` / `push_url` 恒为空。
- **在线人数**：`live_viewers` 表 + 90 秒滑动窗口。客户端进房后每 30 秒 `POST /live/:id/join` 当心跳，
  `total_views` 只在首次进房 +1。
- **封禁**：封在机构上（`sitters.live_banned_at`），同时把该机构所有 `living` 直播间置为 `banned`。

## 三、数据表（迁移 `0020_live_streaming.sql`）

| 表 | 用途 | 关键约束 |
|---|---|---|
| `live_rooms` | 一场直播 | `status ∈ living/ended/banned`；**同一机构只能有一个 living**（部分唯一索引） |
| `live_viewers` | 在线观众 | `(room_id,user_id)` 主键，`last_seen_at` 90s 窗口 |
| `live_messages` | 弹幕 | `status ∈ visible/hidden`，后台可隐藏 |
| `sitters.live_banned_at` / `live_ban_reason` | 直播封禁 | 非空即禁止开播 |

## 四、接口

### 4.1 观看端（任何登录用户）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/live?page=&per_page=&sitter_id=` | 直播中列表（含 `play_hls/play_flv`，不含推流钥匙） |
| GET | `/api/v1/live/:id` | 直播间详情（结束后仍可查，用于回显结束原因） |
| POST | `/api/v1/live/:id/join` | 进房 **兼心跳**（30s 一次），返回最新在线人数 |
| POST | `/api/v1/live/:id/leave` | 离开 |
| GET | `/api/v1/live/:id/messages?after_id=` | 拉弹幕（`after_id` 增量拉取，最多 100 条） |
| POST | `/api/v1/live/:id/messages` | 发弹幕，`content` 1~200 字 |

`LiveRoom` 主要字段：

```json
{
  "id": 4, "sitter_id": 13, "sitter_name": "小满宠物之家",
  "title": "今天带大家看看寄养房间", "cover_url": null,
  "status": "living", "viewer_count": 3, "peak_viewers": 8, "total_views": 21,
  "started_at": "2026-11-05T16:01:30+08:00", "ended_at": null,
  "end_reason": null, "ban_reason": null,
  "play_hls": "http://192.168.3.100:9202/live/<key>.m3u8",
  "play_flv": "http://192.168.3.100:9202/live/<key>.flv",
  "play_rtmp": "rtmp://192.168.3.100:9201/live/<key>"
}
```

### 4.2 机构端（role=sitter）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/sitter/live` | 当前直播 + 最近 20 场历史 + `live_banned/ban_reason` |
| POST | `/api/v1/sitter/live` | 开播，`{title, cover_url}` → 返回 `stream_key/push_url/play_*` |
| PUT | `/api/v1/sitter/live/:id/stop` | 下播 |

错误：已被封禁 → `403 直播权限已被封禁：<原因>`；已有直播 → `409 已有正在进行的直播，请先下播`。

### 4.3 后台（admin）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/admin/live?status=&keyword=` | 全部直播（living 优先），含推流地址 |
| GET | `/api/v1/admin/live/:id` | 详情 + 弹幕（含 hidden）+ 机构封禁状态 |
| PUT | `/api/v1/admin/live/:id/stop` | 强制下播，`{reason}` 选填，通知机构 |
| PUT | `/api/v1/admin/live/:id/ban` | 封禁机构直播，`{reason}` 必填，终止当前直播并通知 |
| PUT | `/api/v1/admin/sitters/:id/live-ban` | `{banned:false}` 解封；`{banned:true,reason}` 封禁 |
| PUT | `/api/v1/admin/live-messages/:mid/hide` | `{hidden:true/false}` 隐藏/恢复弹幕 |

后台操作全部写审计：`LIVE_ADMIN_STOP` / `LIVE_BAN_SITTER` / `LIVE_UNBAN_SITTER` / `LIVE_MESSAGE_MODERATE`。
权限项：`lives.manage`（迁移 0020 已写入 `role_permissions`）。

### 5.3 机构开播步骤

**软件内开播（默认方式）**

1. 机构端「开播」→ `POST /api/v1/sitter/live`，拿到 `room.push_url`
2. App/桌面端进入开播页：
   - Android：`LiveBroadcaster(rtmpUrl)` 自动申请相机/麦克风权限并开始推流（预览即推流画面）
   - 桌面：`CameraBroadcastPanel(rtmpUrl)` 用本机摄像头采集 + 推流 + 预览
3. 观看端 4~10 秒后出画面（HLS 切片 2s）
4. 结束：离开页面自动停推；再调 `PUT /sitter/live/:id/stop`

**备选：外部推流工具（OBS）**

如果临时用其他设备推流，把 `push_url` 拆成「服务器 + 串流密钥」填进工具即可：
服务器 `rtmp://<host>:9201/live`，串流密钥 `<stream_key>`。

## 九、踩坑记录：Android 推流「连接失败：Error configure stream」

真机开播时报：

```
No interface method writeByte(Lkotlin/coroutines/Continuation;)Ljava/lang/Object;
in class Lkotlinx/coroutines/io/ByteWriteChannel; ...
declaration of 'io.ktor.utils.io.ByteWriteChannel' appears in base.apk!classes17.dex
```

**不是业务代码的问题，是依赖版本打架。** RootEncoder `2.5.5` 的 `common` 是按
`io.ktor:ktor-network:2.3.13` 编译的（见其 pom），而本项目自带的 HTTP 客户端是 Ktor `3.6.1`
（Gradle 取高版本，最终落到 classpath 上的是 3.6.1）。Ktor 3 把 `writeByte` 从
`ByteWriteChannel` 的接口方法改成了扩展函数，于是 `RtmpClient` 里编译期的
`invokeinterface ... writeByte` 在运行时找不到目标方法，`connect()` 直接抛异常 ——
表现为预览黑屏 + 「连接失败」。

处理：

1. `rootencoder` 升到 `2.6.6`（编译期 Ktor 3.3.2，与原生的 3.x `ByteWriteChannel` 对齐）；
2. 仍在 `LiveBroadcaster` 里显式 `getStreamClient().setSocketType(SocketType.JAVA)`，
   让 RTMP 走 JDK 原生 Socket，从此不再依赖库与项目两侧 Ktor 版本一致。

顺带修正一处参数误用：`prepareVideo` 的 **5 参重载是 `(w,h,fps,bitrate,rotation)`**，
没有 `iFrameInterval` 的位置，原先写 `prepareVideo(1280,720,30,2_500_000,2)` 等于把旋转角设成 2°。
要设关键帧间隔必须走 6 参重载：`prepareVideo(1280, 720, 30, 2_500_000, 2, 0)`。
