# 宠物寄养服务预约系统 · 数据库设计文档

> 项目代号：宠栖 PatNest  
> 版本：V1.0（2026-10-29）  
> 配套文档：《项目说明.md》《接口文档.md》

---

## 1 设计原则

1. **一切交给 PostgreSQL**：事务隔离、排他约束、原子扣减，避免在应用层堆锁。
2. **软删除 + 不可变历史**：订单金额 / 天数快照落库，机构后续调价不影响历史订单；宠物/评价/用户用 `deleted_at` 软删。
3. **时间戳统一 UTC+8**：所有 `TIMESTAMP` 字段使用 `WITH TIME ZONE`，Go 侧统一 `time.Local = time.FixedZone("CST", 8*3600)`。
4. **命名约定**：表名小写复数（`users`, `sitters`），字段 snake_case，主键 `id BIGSERIAL`，外键以 `_id` 结尾。

## 3 DDL 语句（PostgreSQL 18）

> 以下每条语句均可在空数据库中直接执行。建表前确保已安装扩展：
> ```sql
> CREATE EXTENSION IF NOT EXISTS btree_gist;   -- EXCLUDE USING gist 排他约束依赖
> CREATE EXTENSION IF NOT EXISTS pg_trgm;       -- gin_trgm_ops 模糊搜索依赖
> ```

### 3.1 users — 用户表

> 三角色通过 `role` 列区分，同一账号登录。
> 下表已与 `serverdb/init.sql` + `migrations/0003/0006/0013` 对齐；迁移新增的列以注释标出来源。

```sql
CREATE TABLE users (
    id               BIGSERIAL PRIMARY KEY,
    username         VARCHAR(50)  NOT NULL,
    password_hash    VARCHAR(256) NOT NULL,          -- bcrypt
    nickname         VARCHAR(64),
    phone            VARCHAR(20),                     -- 注册必填（应用层校验）；admin 等预置账号可为空
    email            VARCHAR(128),
    role             user_role    NOT NULL DEFAULT 'owner',
    avatar_url       TEXT,
    status           SMALLINT     NOT NULL DEFAULT 1, -- 1=active, 0=disabled
    login_fail_count SMALLINT     NOT NULL DEFAULT 0,
    locked_until     TIMESTAMPTZ,
    created_at       TIMESTAMPTZ  NOT NULL DEFAULT now(),
    updated_at       TIMESTAMPTZ  NOT NULL DEFAULT now(),
    deleted_at       TIMESTAMPTZ,
    -- 0003：管理员单会话与扩展资料
    session_key      VARCHAR(64),
    points           INT          NOT NULL DEFAULT 0 CHECK (points >= 0),
    address          VARCHAR(255),
    contact_name     VARCHAR(64),
    contact_phone    VARCHAR(20),
    -- 0006：注销冷静期
    cancel_mode      VARCHAR(16),                     -- account | sitter
    cancel_requested_at TIMESTAMPTZ,
    cancel_deadline  TIMESTAMPTZ,
    -- 0013：会话即时吊销点
    token_invalid_at TIMESTAMPTZ,
    CONSTRAINT uq_users_username UNIQUE (username),  -- 0005 起改为部分唯一索引，见下方说明
    CONSTRAINT uq_users_phone    UNIQUE (phone)       -- 含软删行，手机号是永久身份凭证
);

-- 角色过滤
CREATE INDEX idx_users_role ON users (role) WHERE deleted_at IS NULL;
CREATE INDEX idx_users_created ON users (created_at DESC);
CREATE INDEX idx_users_cancel_due ON users (cancel_deadline) WHERE cancel_deadline IS NOT NULL;
COMMENT ON COLUMN users.role IS 'owner=主人, sitter=机构, admin=管理员';
COMMENT ON COLUMN users.session_key IS '管理员当前会话标识；非空时旧会话的令牌全部失效';
COMMENT ON COLUMN users.points IS '积分余额，100 积分 = 1 元';
COMMENT ON COLUMN users.token_invalid_at IS '该时间点之前签发的访问令牌一律失效；NULL 表示从未吊销';
```

> `username` 的唯一性由迁移 `0005` 改为**部分唯一索引**（`WHERE deleted_at IS NULL`），与注册查重口径一致：软删除后允许重新注册同名账号。`init.sql` 里仍写的是 `CONSTRAINT uq_users_username UNIQUE (username)`，执行迁移后该约束会被替换成同名索引。

```sql
-- 0005 之后的实际形态
CREATE UNIQUE INDEX uq_users_username ON users (username) WHERE deleted_at IS NULL;
COMMENT ON INDEX uq_users_username IS '用户名唯一（仅未删除行）：软删除后允许重新注册同名账号';
```

> `refresh_tokens` 表（`user_id` / `token_hash` / `expires_at` / `revoked_at` / `created_at`，`token_hash` 唯一）见 `init.sql` §3.12，本轮刷新令牌轮换与吊销依赖它。

### 3.2 pets — 宠物档案

```sql
CREATE TABLE pets (
    id          BIGSERIAL PRIMARY KEY,
    owner_id    BIGINT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    name        VARCHAR(50)  NOT NULL,
    species     VARCHAR(20)  NOT NULL CHECK (species IN ('cat','dog','other')),
    breed       VARCHAR(100),                     -- 品种/混血描述
    size        VARCHAR(10)  CHECK (size IN ('tiny','small','medium','large','xlarge')),
                                                -- tiny:<2kg small:2-10 medium:10-25 large:25-40 xlarge:>40
    age_month   INT        CHECK (age_month >= 0 AND age_month <= 300),
    vaccinated  BOOLEAN    DEFAULT false,         -- 是否完成基础疫苗
    photo_urls  TEXT[]  DEFAULT '{}',             -- MinIO 图片地址数组
    notes       TEXT,                             -- 备注（用药、过敏等）
    created_at  TIMESTAMP WITH TIME ZONE DEFAULT now(),
    updated_at  TIMESTAMP WITH TIME ZONE DEFAULT now(),
    deleted_at  TIMESTAMP WITH TIME ZONE
);

CREATE INDEX idx_pets_owner ON pets (owner_id) WHERE deleted_at IS NULL;
COMMENT ON COLUMN pets.size IS '体型分类，用于机构匹配和推荐';
COMMENT ON COLUMN pets.vaccinated IS '疫苗接种状态，影响机构准入判断';
```

### 3.3 sitters — 机构信息表

```sql
CREATE TABLE sitters (
    id              BIGSERIAL PRIMARY KEY,
    owner_id        BIGINT NOT NULL REFERENCES users(id),   -- 机构绑定的 user 账号
    user_id         BIGINT NOT NULL REFERENCES users(id),   -- 机构对外展示的联系人 user id
    name            VARCHAR(100) NOT NULL,
    type            VARCHAR(30)  NOT NULL CHECK (type IN ('home','shop','visit','other')),
                                                   -- home=家庭寄养 shop=门店寄养 visit=上门喂养 other=其他
    description     TEXT,
    daily_price     NUMERIC(10,2) NOT NULL DEFAULT 0 CHECK (daily_price >= 0),    -- per_day 模式日单价
    visit_price     NUMERIC(10,2) DEFAULT 0 CHECK (visit_price >= 0),             -- per_visit 模式单次价
    capacity        INT NOT NULL DEFAULT 1 CHECK (capacity >= 1),                 -- 最大容纳数
    price_mode      VARCHAR(20) NOT NULL DEFAULT 'per_day' CHECK (price_mode IN ('per_day','per_visit')),
    address         VARCHAR(255),                                                 -- 详细地址（搜索用）
    latitude        DECIMAL(10,7),                                                -- 纬度
    longitude       DECIMAL(10,7),                                                -- 经度
    avg_score       DECIMAL(3,2) DEFAULT 0 CHECK (avg_score >= 0 AND avg_score <= 5),
    review_count    INT DEFAULT 0,                                                -- 评分聚合计数
    cover_photo_url TEXT,                                                         -- 环境封面图（MinIO）
    detail_photos   TEXT[] DEFAULT '{}',                                          -- 更多环境照片数组
    contact_person    VARCHAR(64),                                                -- 入驻申请联系人姓名
    license_photo_url TEXT,                                                       -- 营业执照照片 URL（入驻资质材料）
    id_card_photo_url TEXT,                                                       -- 联系人身份证照片 URL（入驻资质材料）
    review_note       VARCHAR(255),                                               -- 入驻审核驳回原因
    status          VARCHAR(20) DEFAULT 'active' CHECK (status IN ('pending','active','inactive','banned','rejected')),
                                               -- pending=待审核 active=正常 inactive=停用 banned=封禁 rejected=入驻申请被驳回
    created_at      TIMESTAMP WITH TIME ZONE DEFAULT now(),
    updated_at      TIMESTAMP WITH TIME ZONE DEFAULT now(),
    deleted_at      TIMESTAMP WITH TIME ZONE,
    banned_at       TIMESTAMP WITH TIME ZONE,                                     -- 封禁时间
    banned_reason   VARCHAR(255)                                                -- 封禁原因（合规记录）
);

-- RBAC：机构只能看到自己管理的记录
CREATE INDEX idx_sitters_owner ON sitters (owner_id) WHERE deleted_at IS NULL;
-- 前台排序与搜索常用列，减少 SELECT *
CREATE INDEX idx_sitters_type_score ON sitters (type, avg_score DESC) WHERE deleted_at IS NULL AND status='active';
COMMENT ON COLUMN sitters.price_mode IS '计费模式：per_day(按天) 或 per_visit(按次)，由机构类型驱动';
COMMENT ON COLUMN sitters.status IS '机构审核流程：pending → active/inactive/banned';
```

### 3.4 orders — 订单主表

> 核心业务表，承载状态机和金额快照。

```sql
CREATE TABLE orders (
    id                BIGSERIAL PRIMARY KEY,
    sitter_id         BIGINT NOT NULL REFERENCES sitters(id),
    owner_id          BIGINT NOT NULL REFERENCES users(id),
    sitter_order_no   VARCHAR(64) NOT NULL,                                        -- 机构视角订单号
    status            VARCHAR(20) NOT NULL DEFAULT 'pending_pay' CHECK (status IN (
                                                                 'pending_pay',           -- 待支付
                                                                 'confirmed',             -- 已预约（支付成功）
                                                                 'accepted',              -- 已接单
                                                                 'staying',               -- 寄养中
                                                                 'completed',             -- 已完成（已接回）
                                                                 'evaluated'),            -- 已评价（最终态）
                                                                'cancelled',             -- 已取消（任意阶段都可取消）
                                                                'rejected'),             -- 已拒绝（机构拒单）
    start_date        DATE NOT NULL,
    end_date          DATE NOT NULL CHECK (end_date > start_date),                  -- 含首不含尾
    pet_count         SMALLINT NOT NULL DEFAULT 1 CHECK (pet_count >= 1 AND pet_count <= 10),
    total_amount      NUMERIC(12,2) NOT NULL DEFAULT 0,                              -- 快照金额（前端不信赖）
    total_days        INTEGER DEFAULT 0,                                             -- 快照天数
    estimated_amount  NUMERIC(12,2),                                                 -- 预估金额（下单前展示用，可能未落库）
    payment_status    VARCHAR(20) DEFAULT 'none' CHECK (payment_status IN (
                                                               'none',     -- 未发起支付
                                                               'paid',     -- 已支付
                                                               'refunded')), -- 已退款（当前版本暂不支持）
    cancel_reason     VARCHAR(255),                                                  -- 取消原因（用户可选：行程变更/找不到合适机构/其他）
    cancel_time       TIMESTAMP WITH TIME ZONE,                                      -- 取消时间（自动触发需释放容量）
    accepted_at       TIMESTAMP WITH TIME ZONE,                                      -- 机构确认时间（需要通知主人）
    completed_at      TIMESTAMP WITH TIME ZONE,                                      -- 全部宠物接回时间（触发动作：邀请评价）
    evaluated_at      TIMESTAMP WITH TIME ZONE,                                      -- 主人评价时间（最终状态）
    created_at        TIMESTAMP WITH TIME ZONE DEFAULT now(),
    updated_at        TIMESTAMP WITH TIME ZONE DEFAULT now(),                        -- 每次修改触发 BEFORE UPDATE TRIGGER 更新此列
    deleted_at        TIMESTAMP WITH TIME ZONE,
    CONSTRAINT chk_dates_valid CHECK (end_date - start_date > 0 AND end_date > '2024-01-01')
);

-- 指数增长的唯一订单号
CREATE UNIQUE INDEX idx_orders_sitter_no ON orders (sitter_order_no) WHERE deleted_at IS NULL;
-- 后台管理常用查询条件：按 owner/sitter 过滤、按日期范围筛选
CREATE INDEX idx_orders_owner ON orders (owner_id) WHERE deleted_at IS NULL;
CREATE INDEX idx_orders_sitter ON orders (sitter_id) WHERE deleted_at IS NULL;
-- 状态机快速查询：找出待处理订单（待接单/待支付超时取消）
CREATE INDEX idx_orders_status_active ON orders (status, created_at DESC) WHERE deleted_at IS NULL AND status IN ('confirmed','accepted','staying');
COMMENT ON COLUMN orders.status IS '订单状态机：pending_pay→confirmed→accepted→staying→completed→evaluated 或任一阶段 cancelled/rejected';
COMMENT ON COLUMN orders.total_amount IS '金额快照：下单时后端计算，机构后续调价不影响此值';
COMMENT ON COLUMN orders.cancel_time IS '取消时间，触发 AFTER DELETE TRIGGER 释放相关 capacity 记录';
```

### 3.5 order_pet — 订单-宠物关联表

> 承载排他约束（EXCLUDE 防止重复预约）和每只宠物在订单中的独立信息。

```sql
CREATE TABLE order_pet (
    id          BIGSERIAL PRIMARY KEY,
    order_id    BIGINT NOT NULL REFERENCES orders(id) ON DELETE CASCADE,
    pet_id      BIGINT NOT NULL REFERENCES pets(id) ON DELETE RESTRICT,            -- 宠物不能从已完成订单移除（历史不可篡改）
    stay_date   DATE NOT NULL,                                                     -- 每只宠物的入住日期（通常同订单）
    checkin_time TIME WITHOUT TIME ZONE DEFAULT '09:00:00',                        -- 实际入住房间时间（非必填）
    checkout_time TIME WITHOUT TIME ZONE,                                          -- 实际出房间时间（非必填）
    status      VARCHAR(20) DEFAULT 'assigned' CHECK (status IN (
                                                        'assigned','staying','picked_up','cancelled')),
                                                                        -- assigned=已分配给该宠物 staying=正在寄养 picked_up=已接回 cancelled=已取消（对应订单取消）
    created_at  TIMESTAMP WITH TIME ZONE DEFAULT now(),
    updated_at  TIMESTAMP WITH TIME ZONE DEFAULT now(),
    -- ★ 排他约束：同一宠物同时段不可被重复预约 --
    CONSTRAINT uq_order_pet_exclusive UNIQUE (order_id, pet_id),                   -- 保证一条关联唯一
    CONSTRAINT chk_order_pet_overlap EXCLUDE USING gist (
        pet_id WITH =,                                                          -- pet 必须完全相同才冲突
        daterange(start_date, end_date, '()') WITH &&                          -- 时段重叠则拒绝 INSERT/UPDATE
    )                                                                              -- 注意：daterange 需配合 btree_gist 扩展
);

-- 注意：上面 EXCLUDE USING gist 的写法有语法问题，正确写法：
-- ALTER TABLE order_pet ADD CONSTRAINT uq_stay_conflict EXCLUDE USING gist (
--     pet_id WITH =, daterange(stay_date::date, stay_date::date + INTERVAL '1 day', '[)') WITH &&
-- );
-- 由于 start/end 来自 orders 表，建议在应用层（service）做 overlap 检查并用行级锁（SELECT ... FOR UPDATE）兜底。

CREATE INDEX idx_order_pet_order ON order_pet (order_id) WHERE deleted_at IS NULL;
COMMENT ON COLUMN order_pet.stay_date IS '宠物入住日期，通常等于订单 start_date，支持多宠不同日期的特殊场景';
COMMENT ON COLUMN order_pet.checkin_time IS '实际入住时间（小时:分钟），精确到分钟，便于计算费用';
COMMENT ON COLUMN order_pet.status IS '宠物状态，可与订单整体状态不同步（如部分宠物提前接回）';
```

### 3.6 dynamics — 寄养动态表

> 机构发布宠物在寄养期间的状态更新（文字+照片）。

```sql
CREATE TABLE dynamics (
    id          BIGSERIAL PRIMARY KEY,
    order_id    BIGINT NOT NULL REFERENCES orders(id) ON DELETE CASCADE,
    sitter_user_id BIGINT NOT NULL REFERENCES users(id),                            -- 谁发布的（机构联系人）
    content     TEXT NOT NULL,                                                      -- 文本内容（限 1024 字，防灌水）
    photos      TEXT[] DEFAULT '{}',                                                 -- MinIO 图片数组（建议 ≤ 5 张）
    tags        JSONB DEFAULT '[]',                                                  -- 结构化标签 ["吃饭","玩耍","午睡"]，方便后端检索和前端展示
    created_at  TIMESTAMP WITH TIME ZONE DEFAULT now(),
    updated_at  TIMESTAMP WITH TIME ZONE DEFAULT now()
);

-- 全文搜索：pg_trgm GIN 对 text 列提供相似度排名
CREATE INDEX idx_dynamics_content_search ON dynamics USING gin (content gin_trgm_ops);
-- 按订单时间线展示（最新在前）
CREATE INDEX idx_dynamics_order ON dynamics (order_id, created_at DESC);
-- 可选：为 tags 中的关键词建立 gin 索引（GIN on jsonb @> operator）
CREATE INDEX idx_dynamics_tags ON dynamics USING gin ((tags::text));
COMMENT ON COLUMN dynamics.tags IS '结构化标签数组，用于前端图标渲染和后端关键词搜索';
```

### 3.7 reviews — 评价表

> 仅已完成订单可评价，评分聚合后更新 sitters.avg_score。

```sql
CREATE TABLE reviews (
    id              BIGSERIAL PRIMARY KEY,
    order_id        BIGINT NOT NULL REFERENCES orders(id) UNIQUE,                   -- 一单一评
    sitter_id       BIGINT NOT NULL REFERENCES sitters(id),
    owner_id        BIGINT NOT NULL REFERENCES users(id),
    overall_score   SMALLINT NOT NULL CHECK (overall_score BETWEEN 1 AND 5),       -- 总体评分 1-5
    service_score   SMALLINT NOT NULL CHECK (service_score BETWEEN 1 AND 5),       -- 服务态度（可选维度）
    environment_score SMALLINT NOT NULL CHECK (environment_score BETWEEN 1 AND 5), -- 环境安全（可选维度）
    hygiene_score   SMALLINT NOT NULL CHECK (hygiene_score BETWEEN 1 AND 5),        -- 卫生清洁（可选维度）
    reply_text      TEXT,                                                            -- 机构回复（可选）
    owner_comment   TEXT,                                                            -- 主人评语
    owner_photos    TEXT[] DEFAULT '{}',                                              -- 主人晒图（可选）
    is_visible      BOOLEAN DEFAULT true,                                            -- 是否公开显示（敏感内容可隐藏）
    created_at      TIMESTAMP WITH TIME ZONE DEFAULT now(),
    updated_at      TIMESTAMP WITH TIME ZONE DEFAULT now()                           -- reply_text 更新时由 TRIGGER 刷新
);

CREATE INDEX idx_reviews_sitter ON reviews (sitter_id) WHERE is_visible = true;
CREATE INDEX idx_reviews_owner ON reviews (owner_id) WHERE is_visible = true;
COMMENT ON COLUMN reviews.reply_text IS '机构回复评价内容，提升沟通闭环体验';
```

### 3.8 payments — 支付流水表

```sql
CREATE TABLE payments (
    id              BIGSERIAL PRIMARY KEY,
    order_id        BIGINT NOT NULL REFERENCES orders(id),
    amount          NUMERIC(12,2) NOT NULL,                                           -- 实际支付金额
    method          VARCHAR(20) NOT NULL DEFAULT 'mock' CHECK (method IN (
                                                               'mock',       -- 模拟支付（演示用）
                                                               'alipay',     -- 支付宝（未来对接）
                                                               'wechat')),   -- 微信支付（未来对接）
    transaction_id  VARCHAR(128),                                                     -- 第三方平台交易号（无则为空）
    status          VARCHAR(20) DEFAULT 'created' CHECK (status IN (
                                                             'created','paid','failed','refunded')),
    raw_response    JSONB,                                                             -- 第三方返回原始数据（脱敏存储）
    created_at      TIMESTAMP WITH TIME ZONE DEFAULT now(),
    paid_at         TIMESTAMP WITH TIME ZONE,                                         -- 实际到账时间（回调触发）
    refunded_at     TIMESTAMP WITH TIME ZONE                                          -- 退款时间（若支持）
);

CREATE INDEX idx_payments_order ON payments (order_id) WHERE deleted_at IS NULL;
CREATE INDEX idx_payments_transaction ON payments (transaction_id) WHERE transaction_id IS NOT NULL;
COMMENT ON COLUMN payments.method IS '支付方式：当前只有 mock 模式，正式环境接入 alipay/wechat 插件';
COMMENT ON COLUMN payments.raw_response IS '保留支付网关原始响应，便于排查和对账';
```

### 3.9 notifications — 站内消息表

> 小程序订阅消息不可用时的主要通知通道，支持 push-native 扩展。

```sql
CREATE TABLE notifications (
    id          BIGSERIAL PRIMARY KEY,
    user_id     BIGINT NOT NULL REFERENCES users(id),                               -- 收件人
    type        VARCHAR(50) NOT NULL CHECK (type IN (
                                                       'order_created','order_accepted','order_cancelled',
                                                       'order_rejected','dynamics_published','review_received',
                                                       'system_announcement')),                         -- 消息类型
    title       VARCHAR(128) DEFAULT '',                                             -- 标题（可选）
    body        TEXT NOT NULL,                                                       -- 正文摘要（限 512 字符）
    extra       JSONB DEFAULT '{}',                                                  -- 关联业务 ID 或跳转参数 {"order_id":123}
    scope       notification_scope NOT NULL DEFAULT 'personal',                     -- 归属视角（迁移 0016）：personal / business
    is_read     BOOLEAN DEFAULT false,
    created_at  TIMESTAMP WITH TIME ZONE DEFAULT now()
);

CREATE INDEX idx_notifications_user ON notifications (user_id, created_at DESC);
CREATE INDEX idx_notifications_is_read ON notifications (user_id, is_read) WHERE is_read = false;
CREATE INDEX idx_notifications_user_scope_time ON notifications (user_id, scope, created_at DESC);
COMMENT ON COLUMN notifications.type IS '触发场景：订单创建/确认/取消/拒绝、动态发布、新评价、系统公告';
COMMENT ON COLUMN notifications.body IS '消息正文，Push 推送框内显示的内容';
COMMENT ON COLUMN notifications.scope IS 'personal=个人消息（pet-owner 接口）；business=商家消息（sitter 接口）';
```

`scope` 由迁移 `0016_notification_scope.sql` 引入，同时把 `fn_notify` 扩为 6 参数（第 6 个参数显式指定归属），
并要求所有写入点传值；历史行按 `type` + 标题 + 收件人角色一次性回填。两套接口的列表与已读操作都带 `scope` 条件，
因此个人消息与商家消息的未读数互不干扰；旧 `/api/v1/notifications` 不带该条件，返回全部（详见接口文档 §8）。

归入 `business` 的场景：新订单、订单已支付、新评价、结算、联系请求、发给机构的公告与改期/续费提醒；
其余（订单状态变化、寄养动态、退款、工单回复、发给主人的公告）归入 `personal`。

### 3.10 audit_logs — 审计日志表

> 记录关键操作轨迹，满足评审和溯源要求。后台动作（`fn_audit`）与机构端动作（`writeAudit`，`SITTER_*`）都写这张表。

```sql
CREATE TABLE audit_logs (
    id          BIGSERIAL PRIMARY KEY,
    actor_id    BIGINT REFERENCES users(id) ON DELETE SET NULL,                       -- 操作人；账号被彻底删除后置 NULL
    action      VARCHAR(100) NOT NULL,                                                -- CREATE_ORDER / SITTER_SET_CAPACITY / RESET_PASSWORD...
    resource_type VARCHAR(50) NOT NULL,                                               -- order, sitter, pet, user...
    resource_id BIGINT,                                                               -- 目标 ID；部分动作（导出、权限）为 0/NULL
    detail      JSONB DEFAULT '{}',                                                   -- 变更字段或关键参数
    ip_address  INET,                                                                 -- 由 fn_audit 取当前连接信息
    user_agent  TEXT,
    created_at  TIMESTAMP WITH TIME ZONE DEFAULT now()
);

-- 按操作人和动作分页检索（预留 6 个月归档，当前没有自动清理任务）
CREATE INDEX idx_audit_actor ON audit_logs (actor_id, created_at DESC);
CREATE INDEX idx_audit_action ON audit_logs (action, created_at DESC);
COMMENT ON COLUMN audit_logs.detail IS 'JSON 记录变更字段或关键参数，用于追溯；机构端只记字段名与新值，不存全量快照';
```

> `audit_logs` 的 `actor_id` 在 `init.sql` 里是 `REFERENCES users(id) ON DELETE SET NULL`（不是 `NOT NULL`），彻底删除账号后审计行保留、操作人置空。
> `fn_audit(p_actor_id, p_action, p_resource_type, p_resource_id, p_detail, p_ip)` 只写 `ip_address`，且调用方（`writeAudit` / `fn_audit` 的 Go 调用点）目前都**没有传 IP**，所以 `ip_address` 实际为 `NULL`；`user_agent` 列存在但从未写入。若要真正记录来源 IP，需要让 handler 从 `c.ClientIP()` 取值传入。

### 3.11 sitter_daily_capacity — 每日容量表

> 支撑 4.3 容量校验的核心表。占用与释放都由数据库函数在同一事务内完成，不用分布式锁。

```sql
CREATE TABLE sitter_daily_capacity (
    id              BIGSERIAL PRIMARY KEY,
    sitter_id       BIGINT NOT NULL REFERENCES sitters(id) ON DELETE CASCADE,
    cap_date        DATE NOT NULL,                                  -- 被占用的夜晚（含起点，不含 end_date）
    used            INT NOT NULL DEFAULT 0 CHECK (used >= 0),        -- 该晚已占用名额
    capacity        INT NOT NULL DEFAULT 1 CHECK (capacity >= 1),   -- 该晚生效上限，见 is_override
    is_override     BOOLEAN NOT NULL DEFAULT FALSE,                 -- TRUE=机构显式设置的该日容量
    created_at      TIMESTAMPTZ DEFAULT now(),
    updated_at      TIMESTAMPTZ DEFAULT now(),
    CONSTRAINT uq_sitter_date UNIQUE (sitter_id, cap_date)          -- 一天一条
);
```

口径说明（0015 起）：

- 某晚被占用的判定与下单一致：`start_date <= 该日 < end_date`，占用数累加 `pet_count`；
- `is_override = FALSE` 的行跟随 `sitters.capacity`：机构改默认容量时由
  `trg_sitter_capacity_sync` 同步刷新，`fn_reserve_capacity` 每次占用也会按当前默认值回写；
- `is_override = TRUE` 的行是机构用"按日容量"接口显式设置的覆盖值，系统不再改动，
  但调整时仍要求新容量不低于该日已占用数；
- 上限校验发生在 `fn_reserve_capacity` 内，超限直接 `RAISE`，因此表上没有
  `used <= capacity` 的约束：机构把默认容量调低后，历史行允许短暂处于"已占用 > 上限"的状态，
  此时只是不再接受新订单，不应把已有订单连带回滚失败。

释放路径：取消、拒单、后台退款、超时自动取消、订单完成/评价（归还尚未消费的未来夜间）、
以及后台软删进行中的订单，都会调用 `fn_release_capacity`。

### 3.12 wallets — 用户钱包表（迁移 0017 新增）

> 真实货币余额，每用户一条；机构复用同一张表，但机构收益提现仍走 `sitter_settlements`（方案 A）。
> 余额变更必须在事务内执行，扣减用 `WHERE balance >= amount` 条件更新，`version` 为乐观锁预留。

```sql
CREATE TABLE wallets (
    user_id         BIGINT       PRIMARY KEY REFERENCES users(id) ON DELETE RESTRICT,
    balance         NUMERIC(12,2) NOT NULL DEFAULT 0,      -- 可用余额
    frozen_balance  NUMERIC(12,2) NOT NULL DEFAULT 0,      -- 冻结余额（预留：提现审核中）
    total_recharge  NUMERIC(14,2) NOT NULL DEFAULT 0,      -- 累计充值
    total_consume   NUMERIC(14,2) NOT NULL DEFAULT 0,      -- 累计消费
    version         BIGINT        NOT NULL DEFAULT 0,      -- 乐观锁
    created_at      TIMESTAMPTZ   NOT NULL DEFAULT now(),
    updated_at      TIMESTAMPTZ   NOT NULL DEFAULT now()
);
CREATE INDEX idx_wallets_balance ON wallets (balance DESC);
```

钱包记录在用户首次访问钱包接口时由 `ensureWallet()` 创建，迁移末尾会为存量用户补齐。

### 3.13 wallet_transactions — 资金流水表

> 对账与用户明细的唯一依据。`balance_after` 由服务端在同一事务内计算后写入，客户端不可传入。

```sql
CREATE TABLE wallet_transactions (
    id             BIGSERIAL PRIMARY KEY,
    user_id        BIGINT       NOT NULL REFERENCES wallets(user_id),
    type           TEXT         NOT NULL CHECK (type IN (
                                  'recharge',    -- 充值
                                  'consume',     -- 订单支付
                                  'refund',      -- 退款入账
                                  'withdraw',    -- 提现（预留）
                                  'settle_in',   -- 结算入账（预留）
                                  'adjust_add',  -- 后台调增
                                  'adjust_sub')),-- 后台调减
    amount         NUMERIC(12,2) NOT NULL CHECK (amount > 0),   -- 恒为正，方向看 type
    balance_after  NUMERIC(12,2) NOT NULL,                      -- 变更后余额
    status         TEXT         NOT NULL DEFAULT 'success' CHECK (status IN ('pending','success','failed')),
    channel        TEXT         NOT NULL DEFAULT 'mock' CHECK (channel IN ('mock','wechat','alipay','bank','admin')),
    ref_type       TEXT,        -- order / recharge / withdraw / settlement / admin
    ref_id         BIGINT,
    transaction_id TEXT,        -- 第三方流水号，用于回调对账
    remark         TEXT,
    created_at     TIMESTAMPTZ  NOT NULL DEFAULT now()
);
CREATE INDEX idx_wtx_user_time ON wallet_transactions (user_id, id DESC);
CREATE INDEX idx_wtx_ref       ON wallet_transactions (ref_type, ref_id);
```

### 3.14 recharge_orders — 充值单表

> 充值走"先建单、后确认"两步，`transaction_id UNIQUE` 保证回调重复通知不会重复入账。

```sql
CREATE TABLE recharge_orders (
    id             BIGSERIAL PRIMARY KEY,
    user_id        BIGINT       NOT NULL REFERENCES wallets(user_id),

    channel        TEXT         NOT NULL DEFAULT 'mock' CHECK (channel IN ('mock','wechat','alipay')),
    status         TEXT         NOT NULL DEFAULT 'pending' CHECK (status IN ('pending','paid','failed','closed')),
    transaction_id TEXT UNIQUE,
    paid_at        TIMESTAMPTZ,
    created_at     TIMESTAMPTZ  NOT NULL DEFAULT now(),
    updated_at     TIMESTAMPTZ  NOT NULL DEFAULT now()
);
CREATE INDEX idx_recharge_user ON recharge_orders (user_id, id DESC);
```

演示阶段由 `MockGateway` 同步确认（`POST /pet-owner/wallet/recharge/:id/pay`）；接真实网关后改为异步回调写入。

| 索引 | 类型 | 目的 | 备注 |
|---|---|---|---|
| `uq_users_username` | 部分唯一索引 | 登录名唯一 + 软删后可重用 | `WHERE deleted_at IS NULL`（迁移 0005） |

| `idx_payments_transaction` | 普通 B-tree | 支付回调幂等查询 | NULL 跳过 |

| `idx_recharge_user` | 复合 B-tree | 用户充值单列表 | `(user_id, id DESC)` |

| 所有表 PK `id` | Clustered | 主键聚簇 | 默认排序依据 |

### 5.1 `updated_at` 自动刷新函数（全局复用）

```sql
CREATE OR REPLACE FUNCTION refresh_updated_at() RETURNS TRIGGER AS $$ BEGIN
    NEW.updated_at = now();
    RETURN NEW; END; $$ LANGUAGE plpgsql;

-- 对各表绑定：
ALTER TABLE users ADD CONSTRAINT trg_users_updated_at BEFORE UPDATE ON users FOR EACH ROW EXECUTE FUNCTION refresh_updated_at();
-- （其余表同理）
```

### 5.2 订单取消后释放容量的 TRIGGER（伪代码逻辑）

> Go 端 service 层也会实现同样的释放逻辑（双重保险），这里作为兜底。

```sql
CREATE OR REPLACE FUNCTION release_capacity_on_cancel() RETURNS TRIGGER AS $$
BEGIN
    -- 从 order_pet 找到所有 stay_date，批量 UPDATE sitter_daily_capacity SET used = used - 1 WHERE used > 0
    UPDATE sitter_daily_capacity c
    SET used = LEAST(c.used, greatest(0, c.used - 1))
    FROM (SELECT DISTINCT op.stay_date FROM order_pet op WHERE op.order_id = OLD.id) AS dates(d)
    WHERE c.sitter_id = (SELECT sitter_id FROM orders WHERE id = OLD.id) AND c.date = d.d;
    RETURN OLD; -- 不影响被取消的行
END; $$ LANGUAGE plpgsql;

CREATE TRIGGER trg_release_capacity_on_cancel
    AFTER UPDATE OF status ON orders
    FOR EACH ROW WHEN (OLD.status != 'cancelled' AND NEW.status = 'cancelled')
    EXECUTE FUNCTION release_capacity_on_cancel();
```

### 5.3 评分聚合聚合函数

> `reviews` 插入/更新后触发，重新计算 `sitters.avg_score` 和 `review_count`。

```sql
CREATE OR REPLACE FUNCTION aggregate_review_scores() RETURNS TRIGGER AS $$ BEGIN
    UPDATE sitters SET avg_score = COALESCE((SELECT ROUND(AVG(r.overall_score)::numeric,2) FROM reviews r WHERE r.sitter_id = NEW.sitter_id AND r.is_visible), 0),
                       review_count = COALESCE((SELECT COUNT(*) FROM reviews r WHERE r.sitter_id = NEW.sitter_id AND r.is_visible), 0)
    WHERE id = NEW.sitter_id;
    RETURN NEW; END; $$ LANGUAGE plpgsql;

CREATE TRIGGER trg_aggregate_review_scores AFTER INSERT OR UPDATE OF overall_score, is_visible ON reviews FOR EACH ROW EXECUTE FUNCTION aggregate_review_scores();
```

## 6 数据迁移方案（golang-migrate）

Go 后端使用 [`golang-migrate/migrate`](https://github.com/golang-migrate/migrate) 管理 DDL：

```
server/patnestServer/internal/db/migrations/
├── 000001_init.down.sql      -- 回滚：DROP TABLE ...（按依赖逆序）
├── 000001_init.up.sql        -- 正向：建表 + 索引 + 触发器 + 扩展安装
├── 000002_seed_data.down.sql -- 清空 seed 数据（可选）
└── 000002_seed_data.up.sql   -- 示例机构/测试账号等初始化数据（演示环境）
```

运行方式：
```bash
migrate -path internal/db/migrations -database "postgres://..." up          # 全部应用
migrate -path internal/db/migrations -database "postgres://..." create init sql   # 生成模板文件并自动递增版本号
migrate -path internal/db/migrations -database "postgres://..." up 2         # 指定跳数
migrate -path internal/db/migrations -database "postgres://..." version     # 查看当前版本
```

> 实际仓库中的迁移目录为 `server/patnestServer/serverdb/migrations/`（`init.sql` 为一次性建库脚本，二者需保持同步）。
> 当前最新为 `0017_wallet.sql`：新增 `wallets` / `wallet_transactions` / `recharge_orders` 三张表，
> 并为 `pay_method` 枚举追加 `balance`。`ALTER TYPE ... ADD VALUE` 不能进事务块，执行器对该文件按非事务方式执行（与 0007/0008 一致）。

## 附录 A：数据类型选择说明

| 字段类型 | 选用理由 | 替代方案对比 |
|---|---|---|
| `BIGSERIAL` PK | 演示环境无需 UUID，自增 ID 更简单高效 | UUID v4 适合微服务分布式场景 |
| `NUMERIC(10,2)` 金额 | 财务精度要求高，避免浮点舍入误差 | DECIMAL(10,2) 语义等同 |
| `TEXT[]` 图片数组 | MinIO 上传后直接存入，比额外建附件表轻量 | 单独 `media` 表适合大规模多媒体系统 |
| `JSONB` 扩展字段 | `raw_response`、`extra`、`tags` 结构灵活 | 固定列会丢失弹性 |
| `DATE` vs `TIMESTAMP` | 订单起止只用日期（不含时刻），简化跨月计算 | 如需精确到时分秒可用 `TIMESTAMPTZ` |
