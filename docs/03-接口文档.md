## 0 约定

### 0.1 基础 URL

| 环境 | Base URL | 备注 |
|---|---|---|
| 开发 | `http://localhost:9200/api/v1` | 本机 Compose 起 |
| 演示（公网 IP） | `http://<公网IP>:9200/api/v1` | HTTPS 未就绪前 |
| 正式 | `https://petnest.example.com/api/v1` | 备案域名 + TLS |

### 0.2 统一响应格式

```jsonc
// 成功响应
{
  "code":    0,          // 业务码，0=成功，非 0=见下方错误码表
  "message": "ok",       // 人类可读描述
  "data":    {}           // 业务数据（可省略 null）
}

// 失败响应（HTTP 200，由 code/message 区分）
{
  "code":    10001,
  "message": "参数校验失败",
  "data": {
    "field_errors": { "username": ["不能为空"] }
  }
}
```

### 0.3 分页格式

所有列表接口均支持 `page` / `per_page` 查询参数，默认 `1` / `10`。

```json
{
  "code": 0,
  "data": {
    "items": [],
    "total": 100,
    "page": 1,
    "per_page": 10
  }
}
```

### 0.4 认证与授权

**Header** | **说明**
|---|---|
| `Authorization: Bearer <access_token>` | JWT access token |
| `X-Request-Id` | 可选追踪 ID，用于日志关联 |

双 token 机制：
- **access_token**：有效期 2 小时，放入 `Authorization` 头；无感续期靠 refresh_token。
- **refresh_token**：有效期 7 天，存于 HTTP-only Cookie（`SameSite=Lax; Secure=false(演示)`）；放在 `/auth/refresh` 端点使用。

权限控制：路由级中间件从 JWT payload 中提取 `role`，按以下规则放行：

| 路由前缀 | 要求角色 | 中间件名 |
|---|---|---|
| `/auth/*` | 无需登录 | `Public()` |
| `/pets`, `/orders/**`, `/reviews/**`, `/notifications/**` | `owner` | `OwnerAuth()` |
| `/sitters/me/**`, `/sitters/<id>` (ID 归属当前 sitter) | `sitter` | `SitterAuth()` |
| `/admin/**` | `admin` | `AdminAuth()` |

**注意**：以上为路由层粗粒度检查；service 层还需做行级归属校验（如 `sitter_id == ctx.sitterId`），避免越权。

### 0.5 端点分组规范（按业务角色分三类）

为清晰隔离不同客户端的业务边界、避免路径冲突和权限越权，所有 RESTful 资源根据调用方角色划分为三大命名空间（Namespace）。每个空间对应独立的业务逻辑、数据视图和鉴权策略。

| 命名空间 | 前缀 | 服务对象 | 核心职责 | 典型场景 |
|---|---|---|---|---|
| **主人端** | `/api/v1/pet-owner` | 宠物主人 (Android/iOS/Desktop/小程序) | 浏览机构、建档宠物、创建下单、查看动态、发表评价 | 找寄养、算费用、付模拟款、晒回访体验 |
| **机构端** | `/api/v1/sitter` | 寄养机构/个人服务者 (Web/App) | 店铺资料维护、接单履约、发布寄养动态、查看评价 | 更新封面价目、接受新订单、上传“豆豆吃饭”的照片 |
| **管理端** | `/api/v1/admin` | 平台管理员/审核人员 (Vue3 Web) | 全局监管、商户入驻审核、用户封禁、平台审计日志查询 | 处理投诉、封停违规门店、导出流水对账 |

> ⚠️ **重要约束**：以下两类基础设施端点独立于上述三大分类之外，对所有已登录用户开放，不归属单一角色：
> 1. **认证服务**：统一走 `/api/v1/auth/*`（注册/登录时通过请求体中的 `role` 字段区分主体身份）。
> 2. **文件上传**：统一走 `/api/v1/upload/*`；调用方只上传文件，对象键由后端统一生成为 `uploads/YYYY/MM/{uuid}.{ext}`，返回的公网 URL 直接写入各业务表（宠物头像、机构封面/详情图、动态图片、评价图片等）。

### 0.6 限流策略

Redis 滑动窗口计数器，通过 Gin 中间件实现（不写入 DB）。

| 接口类型 | 限制 | 单位 | 例外 |
|---|---|---|---|
| 注册、登录、密码重置 | 5 次 | /分钟/IP | 超过返回 `429 Too Many Requests` |
| 下单（POST /orders） | 10 次 | /分钟/IP | 防刷单 |
| 上传（POST /upload） | 20 次 | /分钟/User | 防大文件攻击 |
| 其他公共接口 | 200 次 | /分钟/IP | 正常浏览不受影响 |

### 0.7 全局错误码表

| Code | 含义 | HTTP 状态码 | 常见场景 |
|---|---|---|---|
| 0 | 成功 | 200 | — |
| 10001 | 参数校验失败 | 400 | 必填字段缺失、格式不对 |
| 10002 | 请求体无效 | 400 | JSON 解析失败 |
| 10003 | 分页参数非法 | 400 | page/per_page 非正整数 |
| 20001 | 认证失败 | 401 | Token 过期、签名不对、缺失 |
| 20002 | 权限不足 | 403 | 角色不对、无权访问该资源 |
| 30001 | 资源不存在 | 404 | ID 对应记录被删或从未存在 |
| 30002 | 资源冲突 | 409 | 用户名已存在、同一时段重复预约 |
| 40001 | 金额计算异常 | 500 | 后端算费逻辑错误（理论上不应触发） |
| 40002 | 下单事务失败 | 500 | 并发冲突/容量不足回滚 |
| 50001 | 内部错误 | 500 | 未知异常，附带堆栈 |
| 50002 | 第三方调用失败 | 502 | 上传、支付回调网关报错 |

## 1 认证模块 (`/api/v1/auth`)

### 1.1 注册

```http
POST /api/v1/auth/register
Content-Type: application/json
```

**请求体**：

```json
{
  "username": "petlover_001",
  "password": "Str0ngP@ss!",
  "role":     "owner"
}
```

| 字段 | 类型 | 必填 | 校验规则 |
|---|---|---|---|
| username | string | ✅ | 3~50 字符，字母数字下划线 |
| password | string | ✅ | 8~128 字符，至少 1 大写 + 1 小写 + 1 数字 + 1 特殊字符 |
| role | string | ✅ | 枚举值：`owner` / `sitter` / `admin` |

**成功响应 `200 OK`**：
```json
{
  "code": 0,
  "message": "注册成功",
  "data": {
    "user": {
      "id": 1,
      "username": "petlover_001",
      "role": "owner"
    },
    "access_token": "eyJhbGciOiJSUz...",
    "refresh_token_cookie": {
      "name": "refresh_token",
      "value": "eyJhbGciOiJIUz...",
      "httpOnly": true,
      "sameSite": "Lax",
      "maxAge": 604800
    }
  }
}
```

> **注意**：注册接口每分钟限 5 次/IP；admin 账号需预置 seed 数据或环境变量设置（不允许公开注册 admin）。

### 1.2 登录

```http
POST /api/v1/auth/login
Content-Type: application/json
```

**请求体**：
```json
{
  "username": "petlover_001",
  "password": "Str0ngP@ss!"
}
```

**成功响应 `200 OK`**：同上（结构与注册成功完全一致，包含新签发的 access + refresh token）。

> 限频同注册。连续 10 次密码错误锁定账号 15 分钟。

### 1.3 刷新 Token

```http
POST /api/v1/auth/refresh
Cookie: refresh_token=<token>
```

不传 body，只依赖 Cookie 中的 refresh token。

**成功响应 `200 OK`**：
```json
{
  "code": 0,
  "data": {
    "access_token": "new_jwT..."
  }
}
```

### 1.4 登出

```http
POST /api/v1/auth/logout
Authorization: Bearer <token>
```

服务端清除 Redis 中该 token 的黑白名单记录（短 TTL 内不再允许使用）。

**成功响应 `200 OK`**：
```json
{
  "code": 0,
  "message": "已登出"
}
```

## 2 宠物档案管理 (`/api/v1/pet-owner/pets`)

> 仅 **owner** 角色可用。每个 owner 只能读写自己的宠物。

### 2.1 获取宠物列表

```http
GET /api/v1/pet-owner/pets?page=1&per_page=10&species=dog
Authorization: Bearer <token>
```

**路径参数**：无。**查询参数**：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| page | int | 否 | 页码，默认 1 |
| per_page | int | 否 | 每页条数，默认 10，上限 50 |
| species | string | 否 | 过滤器：`cat` / `dog` / `other` |
| name | string | 否 | 模糊匹配宠物名字 |

**成功响应 `200 OK`**：
```json
{
  "code": 0,
  "data": {
    "items": [
      {
        "id": 1,
        "name": "豆豆",
        "species": "dog",
        "breed": "金毛",
        "size": "large",
        "age_month": 18,
        "vaccinated": true,
        "photo_urls": ["https://minio.internal/pets/1/photo1.jpg"],
        "notes": "对花生过敏",
        "created_at": "2026-10-01T09:00:00+08:00",
        "updated_at": "2026-10-15T14:30:00+08:00"
      }
    ],
    "total": 1,
    "page": 1,
    "per_page": 10
  }
}
```

### 2.2 创建宠物档案

```http
POST /api/v1/pet-owner/pets
Authorization: Bearer <token>
Content-Type: application/json
```

**请求体**：
```json
{
  "name":      "豆豆",
  "species":   "dog",
  "breed":     "金毛",
  "size":      "large",
  "age_month": 18,
  "vaccinated": true,
  "notes":     "对花生过敏"
}
```

| 字段 | 类型 | 必填 | 校验规则 |
|---|---|---|---|
| name | string | ✅ | 1~50 字符 |
| species | string | ✅ | `cat` / `dog` / `other` |
| breed | string | 否 | 1~100 字符 |
| size | string | 否 | `tiny/small/medium/large/xlarge` |
| age_month | int | 否 | 0~300 |
| vaccinated | bool | 否 | 默认 false |
| notes | string | 否 | ≤512 字符 |

**成功响应 `200 OK`**：

> ⚠️ 实际用 `200` 保持一致性，此处保留 201 以突出"新建"语义（若框架统一 200 则降级）。

```json
{
  "code": 0,
  "message": "创建成功",
  "data": { /* 同列表项结构 */ }
}
```

### 2.3 修改宠物信息

```http
PUT /api/v1/pet-owner/pets/:id
Authorization: Bearer <token>
Content-Type: application/json
```

**URL 参数**：`id` (BigInt) —— 宠物 ID

请求体同 2.2，但仅传递需要修改的字段（PATCH 语义），其余保持原值不变。

**成功响应 `200 OK`**：

```json
{
  "code": 0,
  "message": "更新成功",
  "data": { /* 更新后的完整宠物对象 */ }
}
```

### 2.4 删除宠物

```http
DELETE /api/v1/pet-owner/pets/:id
Authorization: Bearer <token>
```

执行 **软删除**（SET deleted_at = now()），历史订单不受影响。

**成功响应 `200 OK`**：

```json
{
  "code": 0,
  "message": "删除成功"
}
```

### 2.5 宠物历史寄养记录

```http
GET /api/v1/pet-owner/pets/:id/stays
Authorization: Bearer <token>
```

按宠物维度聚合历史订单（`data.items` 元素含 `order_id/order_no/sitter_id/sitter_name/status/start_date/end_date/total_days/stay_date/total_amount`，`total` 为寄养次数）。

**说明**：宠物对象（列表/详情/新建/修改的响应）现统一携带免疫证明核验回读字段：

| 字段 | 说明 |
|---|---|
| vaccine_urls | 已上传的接种证图片 URL 数组 |
| vaccine_status | `missing` 未上传 / `pending` 待核验 / `verified` 已通过 / `rejected` 被驳回 |
| vaccine_note | 管理员核验备注（驳回原因等） |

### 3.4 我的机构（sitter 管理端）

```http
GET /api/v1/sitter/shop/me
Authorization: Bearer <token>
```

返回当前 sitter 管理的机构信息。无分页。

```http
PUT /api/v1/sitter/shop/me
Authorization: Bearer <token>
Content-Type: application/json
```

更新我的机构信息：名称、描述、地址、价格、照片等。

**请求体示例**：
```json
{
  "name": "安心宠物之家",
  "description": "全新装修",
  "address": "朝阳区XXX",
  "latitude": 39.904200,
  "longitude": 116.407400,
  "daily_price": 55.00,
  "capacity": 6
}
```
`latitude` / `longitude` 为 GCJ-02 坐标，可省略（省略即不改动已存坐标）；
桌面端通过 §3.5 的地理编码接口拿到坐标后再保存。坐标缺失时主人端无法按距离排序，也没有到店导航入口。

### 3.5 地址解析坐标（地理编码）

```http
POST /api/v1/geo/geocode
Authorization: Bearer <token>
Content-Type: application/json
```

**请求体**：

```json
{ "address": "赛罕区大学东街8号", "city": "呼和浩特" }
```

给没有系统定位的客户端（桌面端"机构资料"页）用：后端代理高德 Web 服务地理编码，
`AMAP_KEY` 不出后端。地址少于 4 个字会直接返回参数错误，提示写清楚区/街道。

**成功响应 `200 OK`**：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "latitude": 40.821365,
    "longitude": 111.772564,
    "formatted_address": "内蒙古自治区呼和浩特市赛罕区大学东街",
    "resolved_city": "呼和浩特市",
    "district": "赛罕区",
    "adcode": "150105",
    "level": "街道",
    "from_cache": false
  }
}
```

说明：结果按 `md5(city|地址)` 落 `geocode_cache` 表，半年内同一地址不重复请求高德（`from_cache: true`）；
每账号每分钟最多 20 次真实解析（Redis 未启用时不计数）。

| 状态 | code | 含义 |
|---|---|---|
| 400 | 10001 | 地址过短 / 高德未能解析（需补充城市或区街道） |
| 429 | 42901 | 解析过于频繁 |
| 501 | 50002 | 服务端未配置 `AMAP_KEY` |

### 3.6 地图选点（桌面端）

Compose Desktop 没有内嵌浏览器，桌面端的"在地图中选点"走一次一跳的会话：
客户端建会话 → 系统浏览器打开选点页 → 用户选点回写 → 客户端轮询取结果。

```http
POST /api/v1/geo/pick
Authorization: Bearer <token>
Content-Type: application/json
```

**请求体**（都可省略，省略则从默认城市开始）：

```json
{ "latitude": 40.821365, "longitude": 111.772564, "place_name": "安心宠物之家" }
```

**成功响应 `200 OK`**：

```json
{ "code": 0, "message": "ok", "data": { "token": "3f1c…（32位十六进制）", "path": "/geo/pick/3f1c…", "expires_in": 300 } }
```

`path` 是相对接口根路径的，客户端用自己的 `apiBase` 拼成完整链接后再调用浏览器打开。

```http
GET /api/v1/geo/pick/:token
```

选点页本身（浏览器打开，**无需登录**，凭一次性令牌）。页面提供高德交互地图：搜索地点、点击落点、拖动标记、逆地理回填地址，
点"确认选点"后回写：

```http
POST /api/v1/geo/pick/:token
Content-Type: application/json

{ "latitude": 40.820981, "longitude": 111.774522, "address": "内蒙古自治区呼和浩特市赛罕区大学东街8号" }
```

```http
GET /api/v1/geo/pick-result/:token
Authorization: Bearer <token>
```

桌面端轮询上面这个接口，返回三态之一：

```json
{ "code": 0, "message": "ok", "data": { "status": "pending" } }
{ "code": 0, "message": "ok", "data": { "status": "done", "latitude": 40.820981, "longitude": 111.774522, "formatted_address": "…大学东街8号" } }
{ "code": 0, "message": "ok", "data": { "status": "expired" } }
```

安全与约束：库里只存 `sha256(token)`，明文令牌只在创建响应和链接里出现；会话 5 分钟过期、只有创建者能取走、取走即删；
每账号每分钟最多发起 6 次。坐标仍按 GCJ-02 处理，接口本身不做二次校验之外的坐标猜测。
未配置 `AMAP_JS_KEY` 时创建会话返回 501，桌面端会自动提示改用"按地址解析坐标"。

### 3.7 地图瓦片、静态地图与逆地理编码（桌面端弹框选点）


## 4 订单核心流程 (`/api/v1/orders`)

### 4.1 创建订单

```http
POST /api/v1/pet-owner/orders
Authorization: Bearer <token>
Content-Type: application/json
```

**请求体**：

```json
{
  "sitter_id": 1,
  "start_date": "2026-11-01",
  "end_date":   "2026-11-04",
  "pets": [
    { "pet_id": 1 },
    { "pet_id": 2, "stay_date": "2026-11-02" }
  ]
}
```

| 字段 | 类型 | 必填 | 校验规则 |
|---|---|---|---|
| sitter_id | BigInt | ✅ | 存在的 active 机构 |
| start_date | Date (ISO 8601) | ✅ | ≥ 今天 |
| end_date | Date (ISO 8601) | ✅ | > start_date |
| pets | array | ✅ | ≥ 1 只宠物，pet_id 归属当前 owner |
| pets[].pet_id | BigInt | ✅ | 属于当前登录用户 |
| pets[].stay_date | Date | 否 | 默认等于 start_date |

**后端处理流程**（service 层顺序）：

1. 验证 sitter 存在且 status=`active`
2. 验证 pet_id 归属当前 owner
3. 按 `sitter.price_mode` 计算费用并生成 `estimated_amount`：
   - `per_day`: `(end_date - start_date) × daily_price × pet_count`
   - `per_visit`: `visit_price × pet_count`
4. 生成唯一 `sitter_order_no`（格式 `{prefix}-{YYYYMMDD}-{seq}`）
5. 在事务内：
   - INSERT orders 行（status=`pending_pay`）
   - INSERT order_pet 行（多条）
   - UPDATE sitter_daily_capacity SET used=used+n WHERE ...（原子扣减，失败即 ROLLBACK）
   - INSERT notifications（通知 sitter "收到新订单"）
6. 返回 200 + 预估金额 + 订单号

**成功响应 `200 OK`**：

```json
{
  "code": 0,
  "message": "下单成功，请在 30 分钟内完成支付",
  "data": {
    "order_id":        101,
    "sitter_order_no": "PATN-20261029-0001",
    "estimated_amount": 150.00,
    "total_days":       3,
    "pet_count":        2,
    "sitter_name":      "安心宠物之家",
    "expires_at":       "2026-10-29T10:30:00+08:00"
  }
}
```

> ⚠️ **并发控制**：下单事务中使用了 `SELECT ... FOR UPDATE OF sitter_daily_capacity` 行锁 + capacity 原子扣减检查。并发尝试同一日期同一机构同一宠物的第二次下单会被 EXCLUDE constraint 拦截（如果走 PG 约束路径），或在 service 层 overlap 检查 + 行锁时因 `lock timeout exceeded` 回滚。无论哪种路径都会返回错误码 `409 Conflict`。

### 9.6 订单退款

## 11 Middleware 规范

### 11.1 JWT Auth (`jwt_auth.go`)

- 从 `Authorization: Bearer <token>` 解析 JWT
- 校验签名（RS256）、exp/iat/nbf 时间戳
- 从 payload 提取 `user_id` 和 `role` 写入 `context.Context`
- 黑名单检查：Token 若在 Redis blacklist 中存在则拒绝

```go
func JWTAuth() gin.HandlerFunc {
    return func(c *gin.Context) {
        token := c.GetHeader("Authorization")
        if token == "" || !strings.HasPrefix(token, "Bearer ") {
            c.JSON(401, gin.H{"code": 20001, "message": "missing or invalid authorization header"})
            c.Abort()
            return
        }
        claims, err := validateJWT(strings.TrimPrefix(token, "Bearer "))
        if err != nil {
            c.JSON(401, gin.H{"code": 20001, "message": "invalid or expired token"})
            c.Abort()
            return
        }
        if isBlacklisted(claims.TokenID) {
            c.JSON(401, gin.H{"code": 20001, "message": "token revoked"})
            c.Abort()
            return
        }
        c.Set("user_id", claims.UserID)
        c.Set("role", claims.Role)
        c.Next()
    }
}
```

### 11.2 RBAC Guard (`rbac.go`)

```go
func RequireRole(roles ...string) gin.HandlerFunc {
    return func(c *gin.Context) {
        userRole := c.GetString("role")
        allowed := false
        for _, r := range roles {
            if userRole == r { allowed = true; break }
        }
        if !allowed {
            c.JSON(403, gin.H{"code": 20002, "message": "insufficient permissions"})
            c.Abort()
            return
        }
        c.Next()
    }
}
```

### 11.3 Rate Limit (`ratelimit.go`)

- 基于 Redis `INCR` + `EXPIRE` 的滑动窗口计数
- Key 根据端点类型：`rl:<endpoint>:<IP>` 或 `rl:<endpoint>:<UserID>`
- 超限返回 `429` 并附 Retry-After header

### 11.4 Request ID & Panic Recovery

- `RequestID`：每次请求分配 UUID，贯穿 log 链路
- `Recovery`：catch panic → log stack trace → return `500 Internal Error`

### 12.0 会话与权限规则

**管理员单会话**

- 管理员每次登录都会轮换 `users.session_key`，并吊销该账号之前的 refresh token。
- 旧 access token 再访问任何受保护接口时返回 HTTP 401：

```json
{ "code": 20003, "message": "该管理员账号已在其他设备登录，当前会话已失效" }
```

- 仅 `admin` 角色应用此规则；`owner`、`sitter` 仍支持多端同时登录。
- 管理员登出时清空 `session_key`。

**管理员权限点**

管理端接口在角色校验之后，再按 `role_permissions` 中 `role='admin'` 的权限点校验：

| 路径前缀 | 权限点 |

## 附录 A：计费纯函数规范（Estimate Service）

> 此函数在 KMP `commonMain` 共享层也有纯函数版本（同组测试用例双向对齐）。

```go
package estimate

import "time"

// PriceMode defines how a sitter charges.
type PriceMode string

const (
    PerDay  PriceMode = "per_day"
    PerVisit PriceMode = "per_visit"
)

// EstimateResult holds the calculated order cost.
type EstimateResult struct {
    TotalAmount   float64
    TotalDays     int
    PetCount      int
    UnitPrice     float64
    Breakdown     []BreakdownItem
}

type BreakdownItem struct {
    Type    string  // "day_charge" or "visit_charge"
    Quantity int
    UnitCost float64
    Amount   float64
}

// Calculate returns total estimated cost. NOT idempotent w.r.t. database.
func Calculate(mode PriceMode, startDate, endDate time.Time,
    petCount int, dailyPrice, visitPrice float64) (*EstimateResult, error) {

    if petCount <= 0 || petCount > 10 {
        return nil, fmt.Errorf("pet count must be 1..10")
    }
    days := int(endDate.Sub(startDate).Hours() / 24)
    if days <= 0 {
        return nil, fmt.Errorf("end_date must be after start_date")
    }

    switch mode {
    case PerDay:
        amount := float64(days) * dailyPrice * float64(petCount)
        return &EstimateResult{
            TotalAmount: amount,
            TotalDays:   days,
            PetCount:    petCount,
            UnitPrice:   dailyPrice,
            Breakdown: []BreakdownItem{{Type: "day_charge", Quantity: days * petCount, UnitCost: dailyPrice, Amount: amount}},
        }, nil

    case PerVisit:
        amount := visitPrice * float64(petCount)
        return &EstimateResult{
            TotalAmount: amount,
            TotalDays:   0,
            PetCount:    petCount,
            UnitPrice:   visitPrice,
            Breakdown: []BreakdownItem{{Type: "visit_charge", Quantity: petCount, UnitCost: visitPrice, Amount: amount}},
        }, nil

    default:
        return nil, fmt.Errorf("unsupported price mode: %s", mode)
    }
}
```

**测试用例对照表（KMP 与 Go 后端共用）**：

| 用例编号 | sitter_id | price_mode | start | end | pets | expected_amount | expected_days |
|---|---|---|---|---|---|---|---|
| TC-1 | 1 | per_day | 2026-11-01 | 2026-11-04 | 1 × dog | 150.00 | 3 |
| TC-2 | 1 | per_day | 2026-11-01 | 2026-11-04 | 2 × dogs | 300.00 | 3 |
| TC-3 | 2 | per_day | 2026-11-01 | 2026-11-01 | 1 × cat | 0.00 | 0 *(error)* |
| TC-4 | 3 | per_visit | 2026-11-01 | 2026-11-04 | 2 × cats | 60.00 | 0 |
| TC-5 | 1 | per_day | 2026-11-01 | 2026-11-02 | 1 × large dog | 50.00 | 1 |
| TC-6 | 4 | per_visit | 2026-11-01 | 2026-11-10 | 3 × mixed | 90.00 | 0 |
