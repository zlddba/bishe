## 0 约定

### 0.1 基础 URL

| 环境 | Base URL | 备注 |
|---|---|---|
| 开发 | `http://localhost:9200/api/v1` | 本机 Compose 起 |

| 正式 | `https://petnest.example.com/api/v1` | 备案域名 + TLS |

### 0.2 统一响应格式

```jsonc
// 成功响应
{
  "code":    0,          // 业务码，0=成功，非 0=见下方错误码表
  "message": "ok",       // 人类可读描述
  "data":    {}          // 业务数据（可省略 null）
}

// 失败响应：HTTP 状态码与 code 同时反映错误
// 例：400 + 10001、401 + 20001、403 + 20002、404 + 30001、409 + 30002、429 + 42901、500 + 50001
{
  "code":    10001,
  "message": "参数校验失败",
  "data": { "field_errors": { "username": ["不能为空"] } }
}
```

> 早期版本写作"失败也返回 HTTP 200，靠 code 区分"，与实现不符。当前后端通过 `handler/response.go` 的 `Fail(c, httpStatus, code, msg)` 同时设置真实 HTTP 状态码，客户端应优先按状态码判断，`code` 用于细分。

### 0.3 分页格式

列表接口支持 `page` / `per_page` 查询参数；默认值不统一（公开机构列表 `10`，后台与多数管理列表 `20`，上限多为 `50` 或 `100`），以各接口说明为准。

```json
{
  "code": 0,
  "data": {
    "items": [],
    "total": 100,
    "page": 1,
    "per_page": 10
  }
}
```

### 0.4 认证与授权

| Header | 说明 |
|---|---|
| `Authorization: Bearer <access_token>` | JWT access token |
| `X-Request-Id` | 可选追踪 ID；后端仅允许该头跨域，不生成也不回写 |

双 token 机制：
- **access_token**：有效期默认 30 分钟（`JWT_ACCESS_TTL_MINUTES` 可调），放入 `Authorization` 头。
- **refresh_token**：有效期 7 天，随登录/注册响应体一起返回，由客户端自己保存（桌面端放内存、后台管理端放 `localStorage`）；服务端只存它的 SHA-256，用于换访问令牌和吊销。

客户端的无感续期：访问令牌撞上 401 时，用 refresh_token 调 `/auth/refresh` 换一张新的，再把原请求重放一次；换不到才算登录过期。桌面端和后台管理端都已实现，两端并发请求共用同一次刷新调用。

权限控制：路由级中间件从 JWT payload 中提取 `role`，按以下规则放行（实际注册见 `internal/router/router.go`）：

| 路由前缀 | 要求 | 中间件 |
|---|---|---|
| `/sitters/**`（公开只读）、`/auth/{register,login,refresh}`、`/version`、`/health`、`/geo/pick/:token` | 无需登录 | 无 |
| `/pet-owner/sitters*`（浏览机构） | 任意登录用户 | `JWTAuth()` |
| `/pet-owner/**`（除 `/pet-owner/sitters*`） | `owner` 或 `sitter`（机构可切主人视角） | `JWTAuth()` + `RequireRole("owner","sitter")` |
| `/sitter/**` | `sitter` | `JWTAuth()` + `RequireRole("sitter")` |
| `/admin/**` | `admin` + 模块权限点 | `JWTAuth()` + `RequireRole("admin")` + `AdminPermission()` |
| `/auth/{logout,me,profile,password}`、`/support/**`、`/notifications/**`、`/upload/image`、`/geo/**`（除公开选点页） | 任意登录用户 | `JWTAuth()` |

**注意**：路由级只做角色粗筛；行级归属校验在 handler 内完成（`owner_id = 当前用户`、`mySitterID(user_id)` 反查后带 `sitter_id` 条件、`requireDynamicAccess` 等），不能只靠中间件。

### 0.5 端点分组规范（按业务角色分三类）

为清晰隔离不同客户端的业务边界、避免路径冲突和权限越权，所有 RESTful 资源根据调用方角色划分为三大命名空间（Namespace）。每个空间对应独立的业务逻辑、数据视图和鉴权策略。

| 命名空间 | 前缀 | 服务对象 | 核心职责 | 典型场景 |
|---|---|---|---|---|
| **主人端** | `/api/v1/pet-owner` | 宠物主人 (Android/Desktop/小程序) | 浏览机构、建档宠物、创建下单、查看动态、发表评价 | 找寄养、算费用、付模拟款、晒回访体验 |
| **机构端** | `/api/v1/sitter` | 寄养机构/个人服务者 (Web/App) | 店铺资料维护、接单履约、发布寄养动态、查看评价 | 更新封面价目、接受新订单、上传“豆豆吃饭”的照片 |
| **管理端** | `/api/v1/admin` | 平台管理员/审核人员 (Vue3 Web) | 全局监管、商户入驻审核、用户封禁、平台审计日志查询 | 处理投诉、封停违规门店、导出流水对账 |

> ⚠️ **重要约束**：以下两类基础设施端点独立于上述三大分类之外，对所有已登录用户开放，不归属单一角色：
> 1. **认证服务**：统一走 `/api/v1/auth/*`（注册/登录时通过请求体中的 `role` 字段区分主体身份）。
> 2. **文件上传**：统一走 `/api/v1/upload/*`；调用方只上传文件，对象键由后端统一生成为 `uploads/YYYY/MM/{uuid}.{ext}`，返回的公网 URL 直接写入各业务表（宠物头像、机构封面/详情图、动态图片、评价图片等）。

### 0.6 限流策略

下表的阈值全部以源码为准（`internal/handler/rate_limit.go`、`internal/cache/login_limit.go`、`internal/handler/auth_handler.go`、`internal/handler/geo_*.go`）。计数用 Redis `INCR` + `PEXPIRE` 的固定窗口，不写库。

| 场景 | 计数维度 | 阈值 | 触发后 | 可调项 |
|---|---|---|---|---|
| 注册 `/auth/register` | IP | 10 次/小时 | `429` / `42901` | `REGISTER_RATE_LIMIT` |
| 刷新 `/auth/refresh` | IP | 60 次/小时 | `429` / `42901` | `REFRESH_RATE_LIMIT` |
| 登录失败 | IP + 用户名 | 5 次/10 分钟 | `429` / `42901` | 常量 `LoginFailLimit` |
| 账号锁定 | 用户 | 累计失败 10 次 | 锁 15 分钟，`403` | 常量 `incrementLoginFail` |
| 图片上传 `/upload/image` | 用户 | 60 次/小时 | `429` / `42901` | `UPLOAD_RATE_LIMIT` |
| 地址解析 `/geo/geocode` | 用户 | 20 次/分钟 | `429` / `42901` | 常量 `geocodeRatePerMinute` |
| 静态地图 `/geo/static-map` | 用户 | 120 次/分钟 | `429` / `42901` | 常量 `staticMapRatePerMinute` |
| 地图瓦片 `/geo/tile` | 用户 | 600 次/分钟 | `429` / `42901` | 常量 `tileRatePerMinute` |
| 选点会话 `/geo/pick` | 用户 | 6 次/分钟 | `429` / `42901` | 常量 `geoPickRateMax` |
| 其余接口 | — | 未限流 | — | 毕设量级下加全局中间件只会误伤轮询 |

三点说明：

- **刷新按 IP 而上传按用户**：刷新发生在未登录态，只能按 IP，但访问令牌只有 30 分钟，正常客户端每小时也要刷两三次，所以阈值放宽到 60 以免校园网同出口 IP 下互相挤占。上传已登录，按用户计数才拦得住盗号者批量投放。
- **Redis 未启用时全部放行**：本地开发不依赖 Redis。唯一例外是账号锁定，它写 `users.locked_until`，不依赖 Redis 也生效。
- **登录两层防线**：`IP + 用户名` 的短期计数拦撞库，`users` 表里的累计失败数拦单账号爆破；前者 10 分钟自动衰减，后者要等 15 分钟或由管理员在后台改密时清零。

### 0.7 跨域（CORS）与来源白名单

跨域许可只发给白名单内的来源，由 `middleware/cors.go` 读取环境变量 `CORS_ALLOW_ORIGINS`（逗号分隔）：

| 配置 | 行为 |
|---|---|
| 未设置 | 默认只允许 `http://127.0.0.1:5173`、`http://localhost:5173`（本机 vite dev） |
| 逗号分隔的源列表 | 仅这些来源拿到 `Access-Control-Allow-Origin`，其余不带 CORS 头，浏览器自行拦截 |
| `*` | 放开全部来源（不建议） |
| 请求不带 `Origin` | 照常放行（桌面端、小程序、服务端调用都不受影响） |

本项目用 Bearer 令牌而非 Cookie，所以响应**不再声明 `Access-Control-Allow-Credentials`**；同源部署（后台 dist 与 `/api` 同域）无需任何配置。改动见 `docs/12` §2.1。

### 0.8 全局错误码表

> 只列后端**实际会返回**的码（`handler/response.go` + 各处 `Fail(...)` 调用）。早期文档里的 `10002` / `10003` / `40002` 在代码中没有对应分支，已移除。

| Code | 含义 | HTTP 状态码 | 常见场景 |
|---|---|---|---|
| 0 | 成功 | 200 | — |
| 10001 | 参数校验失败 | 400 | 必填字段缺失、格式不对、最后一个管理员不可降级、容量低于已占用数 |
| 20001 | 认证失败 | 401 | Token 过期/签名不对/缺失、刷新令牌已吊销、账号已禁用或注销 |
| 20002 | 权限不足 | 403 | 角色不对、无权访问该资源、未获模块权限、改管理员账号被拒 |
| 20003 | 管理员会话失效 | 401 | 该管理员已在其他设备登录，`session_key` 已轮换 |
| 30001 | 资源不存在 | 404 | ID 对应记录被删或从未存在；选点链接过期返回 410 |
| 30002 | 资源冲突 | 409 | 用户名/手机号已存在、机构资料重复创建、时间段重复结算 |
| 40001 | 金额计算异常 | 500 | 后端算费逻辑错误（理论上不应触发） |
| 42901 | 请求过于频繁 | 429 | 注册/刷新/登录失败/上传/地理编码/地图/选点触发限流 |
| 50001 | 内部错误 | 500 | 未知异常、数据库或对象存储失败 |
| 50002 | 第三方/配置缺失 | 501 | 未配置 `AMAP_KEY` / `AMAP_JS_KEY`；上传/支付网关报错 |

## 1 认证模块 (`/api/v1/auth`)

### 1.1 注册

```http
POST /api/v1/auth/register
Content-Type: application/json
```

**请求体**：

```json
{
  "username": "petlover_001",
  "password": "Str0ngP@ss!",
  "role":     "owner"
}
```

| 字段 | 类型 | 必填 | 校验规则 |
|---|---|---|---|
| username | string | ✅ | 3~50 字符 |
| password | string | ✅ | 8~128 字符（后端只校验长度，不强制大小写/数字/符号组合） |
| role | string | ✅ | 只能为 `owner` / `sitter`；传 `admin` 返回 403「不允许注册管理员账号」 |
| nickname | string | 否 | 展示名称 |
| phone | string | 否 | 中国大陆手机号（`^1[3-9]\d{9}$`），全表唯一（含软删行），重复返回 409 |

**成功响应 `200 OK`**：
```json
{
  "code": 0,
  "message": "registration successful",
  "data": {
    "user": {
      "id": 1,
      "username": "petlover_001",
      "nickname": "",
      "role": "owner"
    },
    "access_token": "eyJhbGciOiJIUzI1...",
    "refresh_token": "eyJhbGciOiJIUzI1...",
    "expires_in": 1800
  }
}
```

> **注意**：注册接口按 IP 限流，默认 10 次/小时（`REGISTER_RATE_LIMIT` 可调），超出返回 429；admin 账号需预置 seed 数据或环境变量设置（不允许公开注册 admin）。

### 1.2 登录

```http
POST /api/v1/auth/login
Content-Type: application/json
```

**请求体**：
```json
{
  "username": "petlover_001",
  "password": "Str0ngP@ss!",
  "client": "app"
}
```

| 字段 | 说明 |
|---|---|
| `client` | 可选。`app` 表示桌面/手机客户端，管理员账号用它登录会被 403 拒绝；留空视为管理后台 |

**成功响应 `200 OK`**：结构同注册（`user` + `access_token` + `refresh_token` + `expires_in`），管理员额外带 `single_session: true`；若登录顺带撤销了冷静期内的注销申请，还会带 `cancel_withdrawn: true`。

> 登录失败有两层限制：① 按 `IP + 用户名` 在 Redis 计数（`login:fail:*`），5 次/10 分钟内再试直接返回 429；② 账号维度 `users.login_fail_count` 累计到 10 次锁定 15 分钟，返回 403。登录成功会同时清掉这两处状态。

### 1.3 刷新 Token

```http
POST /api/v1/auth/refresh
Content-Type: application/json
```

刷新令牌放在请求体（为兼容旧客户端，也接受表单字段 `refresh_token` 和同名 Cookie）。按 IP 限流，默认 60 次/小时（`REFRESH_RATE_LIMIT`）。

**成功响应 `200 OK`**：
```json
{
  "code": 0,
  "data": {
    "access_token": "eyJhbGciOiJIUz...",
    "refresh_token": "eyJhbGciOiJIUz...",
    "expires_in": 1800
  }
}
```

**刷新令牌轮换**：响应里的 `refresh_token` 是**新签发**的一张，客户端必须用它覆盖本地保存的旧值。旧的那张在本次请求返回时当场作废，再拿它来刷新会得到 `401 令牌已被吊销`。
这样即使刷新令牌泄漏，它能被利用的窗口也只有"下一次正常刷新之前"。

两条实际影响：

- 客户端必须实现"收到 401 → 刷新 → 用新令牌重放"，并把轮换下来的 `refresh_token` 存回去；两端（KMP 的 `ApiClient`、后台的 `src/api/index.js`）都已这样做，详见 `docs/12` §2.8、§2.9。
- 同一账号开多个浏览器标签页时，先刷新的那个拿到新令牌，落后的那个手里的已成废票，会掉回登录页。这是轮换的固有代价；管理员本来就是单会话，普通用户重登一次即可。

### 1.4 登出

```http
POST /api/v1/auth/logout
Authorization: Bearer <token>
```

服务端做真正的会话吊销：该账号所有 `refresh_tokens` 置 `revoked_at`，`users.token_invalid_at` 推到当前时刻，此前签发的访问令牌即刻失效（中间件比对 `iat`，留 1 分钟时钟宽容窗口）。本地清令牌只是配套动作，客户端就算没清也进不来了。

**成功响应 `200 OK`**：
```json
{
  "code": 0,
  "message": "已登出"
}
```

## 2 宠物档案管理 (`/api/v1/pet-owner/pets`)

> 角色为 `owner` 或 `sitter` 均可访问（机构账号可以切到主人视角）。数据按当前 `user_id` 过滤，不会串号。

| 参数 | 类型 | 必填 | 说明 |

```json
    ],
    "total": 1,
    "page": 1,
    "per_page": 10
```

| 字段 | 类型 | 必填 | 校验规则 |

| age_month | int | 否 | 0~300 |

**成功响应 `200 OK`**：


执行 **软删除**（SET deleted_at = now()），历史订单不受影响。

**成功响应 `200 OK`**：



**说明**：宠物对象（列表/详情/新建/修改的响应）现统一携带免疫证明核验回读字段：

| 字段 | 说明 |
|---|---|
| vaccine_urls | 已上传的接种证图片 URL 数组 |
| vaccine_status | `missing` 未上传 / `pending` 待核验 / `verified` 已通过 / `rejected` 被驳回 |
| vaccine_note | 管理员核验备注（驳回原因等） |

## 3 机构展示与筛选 (`/api/v1/pet-owner/sitters`)

| 状态 | code | 含义 |
|---|---|---|
| 400 | 10001 | 地址过短 / 高德未能解析（需补充城市或区街道） |
| 429 | 42901 | 解析过于频繁 |
| 501 | 50002 | 服务端未配置 `AMAP_KEY` |

### 3.6 地图选点（桌面端）

Compose Desktop 没有内嵌浏览器，桌面端的"在地图中选点"走一次一跳的会话：
客户端建会话 → 系统浏览器打开选点页 → 用户选点回写 → 客户端轮询取结果。

```http
POST /api/v1/geo/pick
Authorization: Bearer <token>
Content-Type: application/json
```

**请求体**（都可省略，省略则从默认城市开始）：

```json

```

**成功响应 `200 OK`**：

```json
{ "code": 0, "message": "ok", "data": { "token": "3f1c…（32位十六进制）", "path": "/geo/pick/3f1c…", "expires_in": 300 } }
```

`path` 是相对接口根路径的，客户端用自己的 `apiBase` 拼成完整链接后再调用浏览器打开。

```http
GET /api/v1/geo/pick/:token
```

选点页本身（浏览器打开，**无需登录**，凭一次性令牌）。页面提供高德交互地图：搜索地点、点击落点、拖动标记、逆地理回填地址，
点"确认选点"后回写：

```http
POST /api/v1/geo/pick/:token
Content-Type: application/json

{ "latitude": 40.820981, "longitude": 111.774522, "address": "内蒙古自治区呼和浩特市赛罕区大学东街8号" }
```

```http
GET /api/v1/geo/pick-result/:token
Authorization: Bearer <token>
```

桌面端轮询上面这个接口，返回三态之一：

```json
{ "code": 0, "message": "ok", "data": { "status": "pending" } }
{ "code": 0, "message": "ok", "data": { "status": "done", "latitude": 40.820981, "longitude": 111.774522, "formatted_address": "…大学东街8号" } }
{ "code": 0, "message": "ok", "data": { "status": "expired" } }
```

安全与约束：库里只存 `sha256(token)`，明文令牌只在创建响应和链接里出现；会话 5 分钟过期、只有创建者能取走、取走即删；
每账号每分钟最多发起 6 次。坐标仍按 GCJ-02 处理，接口本身不做二次校验之外的坐标猜测。
未配置 `AMAP_JS_KEY` 时创建会话返回 501，桌面端会自动提示改用"按地址解析坐标"。

## 4 订单核心流程 (`/api/v1/orders`)

### 4.1 创建订单

```http
POST /api/v1/pet-owner/orders
Authorization: Bearer <token>
Content-Type: application/json
```

**请求体**：

```json
{
  "sitter_id": 1,
  "start_date": "2026-11-01",
  "end_date":   "2026-11-04",
  "pets": [
    { "pet_id": 1 },
    { "pet_id": 2, "stay_date": "2026-11-02" }
  ]
}
```

| 字段 | 类型 | 必填 | 校验规则 |
|---|---|---|---|
| sitter_id | BigInt | ✅ | 存在的 active 机构 |
| start_date | Date (ISO 8601) | ✅ | ≥ 今天 |
| end_date | Date (ISO 8601) | ✅ | > start_date |
| pets | array | ✅ | ≥ 1 只宠物，pet_id 归属当前 owner |
| pets[].pet_id | BigInt | ✅ | 属于当前登录用户 |
| pets[].stay_date | Date | 否 | 默认等于 start_date |

**后端处理流程**（service 层顺序）：

1. 验证 sitter 存在且 status=`active`
2. 验证 pet_id 归属当前 owner
3. 按 `sitter.price_mode` 计算费用并生成 `estimated_amount`：
   - `per_day`: `(end_date - start_date) × daily_price × pet_count`
   - `per_visit`: `visit_price × pet_count`
4. 生成唯一 `sitter_order_no`（格式 `{prefix}-{YYYYMMDD}-{seq}`）
5. 在事务内：
   - INSERT orders 行（status=`pending_pay`）
   - INSERT order_pet 行（多条）
   - UPDATE sitter_daily_capacity SET used=used+n WHERE ...（原子扣减，失败即 ROLLBACK）
   - INSERT notifications（通知 sitter "收到新订单"）
6. 返回 200 + 预估金额 + 订单号

**成功响应 `200 OK`**：

```json
{
  "code": 0,
  "message": "下单成功，请在 30 分钟内完成支付",
  "data": {
    "order_id":        101,
    "sitter_order_no": "PATN-20261029-0001",
    "estimated_amount": 150.00,
    "total_days":       3,
    "pet_count":        2,
    "sitter_name":      "安心宠物之家",
    "expires_at":       "2026-10-29T10:30:00+08:00"
  }
}
```

> ⚠️ **并发控制**：下单事务中使用了 `SELECT ... FOR UPDATE OF sitter_daily_capacity` 行锁 + capacity 原子扣减检查。并发尝试同一日期同一机构同一宠物的第二次下单会被 EXCLUDE constraint 拦截（如果走 PG 约束路径），或在 service 层 overlap 检查 + 行锁时因 `lock timeout exceeded` 回滚。无论哪种路径都会返回错误码 `409 Conflict`。

## 7 图片上传 (`/api/v1/upload`)

### 7.1 上传图片至 MinIO

```http
POST /api/v1/upload/image
Authorization: Bearer <token>
Content-Type: multipart/form-data
```

**表单字段**：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| file | File | ✅ | 图片文件（jpg/jpeg/png/gif/webp，≤5MB） |

**后端处理**：

1. 按登录用户限流，默认 60 次/小时（`UPLOAD_RATE_LIMIT` 可调），超限返回 `429` / `42901`
2. 校验扩展名与文件大小（图片 ≤ 5MB，格式 jpg/jpeg/png/gif/webp）
3. 读取文件头 magic bytes 复核真实类型（PNG / JPEG / GIF / WEBP）：认不出返回 400，认出但与扩展名不符同样返回 400
4. 按 `uploads/YYYY/MM/{uuid}.{ext}` 生成对象键，扩展名与 `Content-Type` 一律取嗅探结果
5. 上传 MinIO bucket `patnest-uploads`
6. 返回可公网访问的 URL（桶已设置匿名只读策略）

**失败响应**：

| 状态 | code | 含义 |
|---|---|---|
| 400 | 10001 | 未选文件 / 超过 5MB / 扩展名不支持 / 内容不是图片 / 扩展名与内容不符 |
| 429 | 42901 | 上传过于频繁（按用户计数） |
| 500 | 50001 | 对象存储未初始化或写入失败 |

**成功响应 `200 OK`**：

```json
{
  "code": 0,
  "message": "上传成功",
  "data": {
    "url": "http://zdz.linkzdsada.dpdns.org:9000/patnest-uploads/uploads/2026/10/a1b2c3d4-xxxx.jpg",
    "key": "uploads/2026/10/a1b2c3d4-xxxx.jpg",
    "size": 245760,
    "name": "photo.jpg"
  }
}
```

### 9.6 订单退款

```http
POST /api/v1/admin/orders/:id/refund
Content-Type: application/json
```

```json
{
  "amount": 150.00,
  "reason": "机构临时停业，全额退款"

```

- 同时给下单主人推送一条退款通知。
- 返回 `refund_amount`、`refund_type`、`transaction_id` 与退款后的订单状态。

## 11 Middleware 规范

### 11.1 JWT Auth (`middleware/jwt.go`)

- 从 `Authorization: Bearer <token>` 解析 JWT，签名算法 HS256（密钥 `JWT_SECRET`）
- 校验 `exp` / `iat`，并确认 `issuer` 为 `patnest`（访问令牌）或 `patnest-refresh`（刷新令牌）
- 从 payload 提取 `user_id`、`role`、`session_key` 写入 gin context
- **无状态会话校验**：不再维护 jti 黑名单。每次请求按主键查一次 `users`，比对 `status`、`deleted_at` 与 `token_invalid_at`（令牌 `iat` 早于吊销点即 401，留 1 分钟时钟宽容窗口）
- 管理员额外校验 `session_key` 与库中当前值一致，不一致返回 `20003`

```go
// 实际实现见 internal/middleware/jwt.go
func JWTAuth() gin.HandlerFunc {
    return func(c *gin.Context) {
        // 1) 取 Bearer token
        // 2) ParseToken → 校验签名与 exp
        // 3) admin 额外校验 session_key
        // 4) AccountUsable(userID, iat) → status/deleted_at/token_invalid_at
        // 5) 写入 user_id / role / session_key / token_issued_at
    }
}
```

### 11.2 RBAC Guard (`middleware/jwt.go` + `middleware/permission.go`)

- `RequireRole(roles...)`：路由级角色校验，不匹配返回 `403` / `20002`
- `AdminPermission()`：管理员按 `role_permissions` 的模块权限点二次校验，内置 `admin` 始终放行

```go
func RequireRole(roles ...string) gin.HandlerFunc {
    return func(c *gin.Context) {
        userRole, exists := c.Get("role")
        if !exists {
            c.JSON(403, gin.H{"code": 20002, "message": "缺少角色信息"})
            c.Abort()
            return
        }
        for _, r := range roles {
            if userRole.(string) == r {
                c.Next()
                return
            }
        }
        c.JSON(403, gin.H{"code": 20002, "message": "没有访问该功能的权限"})
        c.Abort()
    }
}
```

### 11.3 Rate Limit (`handler/rate_limit.go`)

- 基于 Redis `INCR` + `PEXPIRE` 的固定窗口计数（`cache.IncrWindow`），不写库
- 两种维度：`ipRateLimit` → `rl:<action>:<IP>`；`subjectRateLimit` → `rl:<action>:<subject>`
- Redis 未启用或命令报错时**放行**，本地开发不受影响
- 超限返回 `429` / `42901`；当前实现未附 `Retry-After` 响应头
- 阈值与覆盖变量见 §0.6

### 11.4 日志与 Panic Recovery

- 使用 `gin.Logger()` 输出访问日志，`gin.Recovery()` 捕获 panic 并返回 `500` / `50001`
- 请求追踪头 `X-Request-Id` 在 CORS 中间件里被列入 `Access-Control-Allow-Headers`，但后端目前**没有生成/回写该头**，也没有独立 `RequestID` 中间件；需要链路追踪时自行在 Nginx 或网关侧生成
- handler 内的关键失败路径用 `log.Printf("[函数名] ...")` 记录原始错误（如订单扫描失败、刷新令牌吊销失败），避免错误被 4xx/5xx 笼统覆盖

### 12.0 会话与权限规则

**管理员单会话**

- 管理员每次登录都会轮换 `users.session_key`，并吊销该账号之前的 refresh token。
- 旧 access token 再访问任何受保护接口时返回 HTTP 401：

```json
{ "code": 20003, "message": "该管理员账号已在其他设备登录，当前会话已失效" }
```

- 仅 `admin` 角色应用此规则；`owner`、`sitter` 仍支持多端同时登录。
- 管理员登出时清空 `session_key`。

**管理员权限点**

管理端接口在角色校验之后，再按 `role_permissions` 中 `role='admin'` 的权限点校验：

| 路径前缀 | 权限点 |
|---|---|
| `GET /admin/users` | `users.read` |
| `POST/PUT/DELETE /admin/users/**` | `users.write` |
| `/admin/sitters/**` | `sitters.manage` |
| `/admin/orders/**` | `orders.manage` |
| `/admin/pets/**` | `pets.verify` |
| `/admin/dynamics/**` | `dynamics.moderate` |
| `/admin/reviews/**` | `reviews.moderate` |
| `/admin/coupons/**` | `coupons.manage` |
| `/admin/notifications/**`、`/admin/notification-templates/**`、`/admin/push-tasks/**` | `notifications.manage` |
| `/admin/refunds/**` | `refunds.approve` |
| `/admin/tickets/**` | `tickets.handle` |
| `/admin/settlements/**` | `settlements.manage` |
| `/admin/export/**`、`/admin/audit` | `audit.read` |
| `/admin/permissions`、`/admin/system/**`、`/admin/updates/**` | `system.settings` |

内置超级管理员用户名 `admin` 始终放行；`users.read`、`system.settings` 不允许被关闭，避免把后台锁死。

**管理员账号保护**

- 改动 `admin` 角色账号的**角色、状态、密码**，只有内置 `admin` 账号可以操作；其余管理员即使有 `users.write` 也会返回 `403` / `20002`。
- 不允许禁用或降级系统中**最后一个可用管理员**（`role='admin' AND status=1 AND deleted_at IS NULL` 且排除自身后为 0 时返回 `400` / `10001`）。
- 内置 `admin` 账号不可删除、不可彻底删除；其余管理员账号的彻底删除同样只有内置 `admin` 可做。
- 保护逻辑集中在 `handler/admin_guard.go`（`guardPrivilegedWrite` / `guardPasswordReset`），细节见 `docs/12` §2.3。

**会话吊销（禁用 / 删除 / 重置密码 / 登出 / 申请注销）**

这些动作统一调用 `revokeAllSessions(userID)`：该账号所有 `refresh_tokens` 置 `revoked_at`，`users.token_invalid_at` 推到 `now()`，此前签发的访问令牌即刻 401。

自己修改密码（`PUT /auth/password`）走 `revokeSessionsBefore(当前令牌 iat)`：其它设备需重新登录，**当前设备不被踢下线**。判定规则与 1 分钟时钟宽容窗口见 `docs/12` §2.6。

改期请求：

```json

```

改期只让**住宿基础价的变化**进入订单金额：加购服务费、优惠券与积分抵扣随原单保持不变。
已支付订单若改到更贵的档期会被拒绝（提示联系平台补差价），待支付订单直接按新金额支付。

续费请求：

```json
{ "end_date": "2026-11-20" }
```

续费只对**新增的那一段服务**计费，并立即收款（mock 支付与 `PUT /orders/{id}/pay` 同口径）：

- 按天机构：逐日累加 `old_end_date` 到 `end_date` 之间的夜间价格，照常套用节假日上浮规则；
- 按次机构：视为再购买一次服务，收 `visit_price × pet_count`；
- 原订单的加购服务费、优惠券抵扣、积分抵扣保持不动，`total_amount` 只在这个差价之上累加，
  不会被整段住宿基础价覆盖；已住过的天数不按机构当前调价重算。

差价写入一条 `status = paid` 的 `payments` 流水（`transaction_id` 形如 `RENEW-20261120-<order_id>`），
因此后台看到的订单金额与实收流水始终一致，退款上限也据此校验。
仅 `payment_status = paid` 且未结束、未取消的订单可续费；`pending_pay` 请先支付。

续费响应：

```json
{
  "order_id": 32,
  "end_date": "2026-11-20",
  "total_days": 12,
  "total_amount": 1010.00,
  "extra_days": 3,
  "extra_amount": 90.00,
  "transaction_id": "RENEW-20261120-32"
}
```

退款申请：

```json
{ "amount": 200.00, "reason": "行程变更，无法按时送宠" }
```


## 附录 A：计费纯函数规范（Estimate Service）

> 此函数在 KMP `commonMain` 共享层也有纯函数版本（同组测试用例双向对齐）。

```go
package estimate

import "time"

// PriceMode defines how a sitter charges.
type PriceMode string

const (
    PerDay  PriceMode = "per_day"
    PerVisit PriceMode = "per_visit"
)

// EstimateResult holds the calculated order cost.
type EstimateResult struct {
    TotalAmount   float64
    TotalDays     int
    PetCount      int
    UnitPrice     float64
    Breakdown     []BreakdownItem
}

type BreakdownItem struct {
    Type    string  // "day_charge" or "visit_charge"
    Quantity int
    UnitCost float64
    Amount   float64
}

// Calculate returns total estimated cost. NOT idempotent w.r.t. database.
func Calculate(mode PriceMode, startDate, endDate time.Time,
    petCount int, dailyPrice, visitPrice float64) (*EstimateResult, error) {

    if petCount <= 0 || petCount > 10 {
        return nil, fmt.Errorf("pet count must be 1..10")
    }
    days := int(endDate.Sub(startDate).Hours() / 24)
    if days <= 0 {
        return nil, fmt.Errorf("end_date must be after start_date")
    }

    switch mode {
    case PerDay:
        amount := float64(days) * dailyPrice * float64(petCount)
        return &EstimateResult{
            TotalAmount: amount,
            TotalDays:   days,
            PetCount:    petCount,
            UnitPrice:   dailyPrice,
            Breakdown: []BreakdownItem{{Type: "day_charge", Quantity: days * petCount, UnitCost: dailyPrice, Amount: amount}},
        }, nil

    case PerVisit:
        amount := visitPrice * float64(petCount)
        return &EstimateResult{
            TotalAmount: amount,
            TotalDays:   0,
            PetCount:    petCount,
            UnitPrice:   visitPrice,
            Breakdown: []BreakdownItem{{Type: "visit_charge", Quantity: petCount, UnitCost: visitPrice, Amount: amount}},
        }, nil

    default:
        return nil, fmt.Errorf("unsupported price mode: %s", mode)
    }
}
```

| TC-2 | 1 | per_day | 2026-11-01 | 2026-11-04 | 2 × dogs | 300.00 | 3 |
| TC-3 | 2 | per_day | 2026-11-01 | 2026-11-01 | 1 × cat | 0.00 | 0 *(error)* |
