# PatNest 宠栖 v2.0.1

v2.0.0 之后的第一个维护版本。这一版**不涉及服务端接口与数据库变更**，全部改动集中在桌面客户端的分发体验：让安装包真正做到开箱即用，并补齐 Linux 平台的分发格式。

## 更新内容

### 桌面客户端不再需要 `.env`，也不需要安装 Java

v2.0.0 的桌面端把接口地址设计成了运行时必填项：环境变量或 `.env` 都没有时会直接抛异常，安装后必须手工在程序目录旁放一份配置文件。v2.0.1 改为**构建期固化**：

- 打包时把接口地址写成启动器的 `-Dpatnest.api.base=...`，随安装包一起分发；
- 启动时按「环境变量 `PATNEST_API_BASE` → `.env` → 构建期固化值 → 内置默认地址」依次取值，**任何情况下都不会因缺少配置而启动失败**；
- 想临时指向另一台后端，仍可用环境变量或 `.env` 覆盖，无需重新打包；
- 顺带修正了几处只在 `.env` 语境下才准确的错误提示文案。

再次说明运行依赖：deb / rpm / msi / dmg / tar.gz / AppImage 都通过 `jlink` 自带裁剪后的 JVM 运行时，**用户机器不需要安装 JDK 或 JRE**。系统只需提供常规原生库（glibc、X11/GTK、字体）；AppImage 在少数发行版上还需要 `libfuse2`。

### Linux 分发格式补齐

| 格式 | 说明 |
| --- | --- |
| `.deb` | Debian / Ubuntu 系，`sudo dpkg -i` 或软件中心安装 |
| `.rpm` | Fedora / RHEL / openSUSE 系 |
| `.AppImage` | 单文件，赋予可执行权限后直接运行，无需安装 |
| `.tar.gz` | 免安装绿色版，解压后运行 `bin/` 下的启动器 |

四种格式由同一次 Linux 构建产出，避免重复编译。其中 `.AppImage` 是用 `appimagetool` 把 jpackage 生成的 app-image 目录封装而成（Compose Desktop 自带的 `TargetFormat.AppImage` 指的是解包目录，不是单文件包）。

### 版本号统一

管理后台、小程序工程、Android `versionName`、桌面安装包 `packageVersion` 全部对齐到 `2.0.1`；客户端版本号由发布 tag 注入，后续发版不需要逐处手改。

## 升级说明

- **服务端**：无需任何操作，没有新增数据库迁移，也没有接口变更；升级部署包可直接沿用现有 `.env` 与数据卷。
- **桌面端**：直接覆盖安装；v2.0.0 用户建议升级，升级后可删掉原先手工放置的 `.env`。
- **绿色版使用**：
  ```bash
  tar -xzf patnest-desktop-2.0.1-linux-x64.tar.gz
  cd patnest-desktop-2.0.1-linux-x64
  ./bin/team.wd.atnestapp
  ```
- **AppImage 使用**：
  ```bash
  chmod +x PatNest-2.0.1-x86_64.AppImage
  ./PatNest-2.0.1-x86_64.AppImage
  ```
- **换后端地址**（可选）：启动时设置 `PATNEST_API_BASE=https://<host>:9200/api/v1`，或在程序目录放一份 `.env`。
- **小程序**：下载工程包后用 HBuilderX 重新导入发行。

## 已知限制

沿用 v2.0.0 的范围，另补充两条：

- 支付仍为模拟网关，不接真实资金渠道；
- 演示环境应用服务器与数据库跨地域，列表接口首屏约 1.5~3 秒；
- 桌面端没有图形化的「修改服务地址」入口，长期换环境建议用环境变量或重新构建；
- macOS dmg 由 arm64 runner 产出，仅适用于 Apple Silicon；
- 未做大规模并发压测。

## 校验

部署包内的 `update-manifest.json` 记录了 API、迁移工具与管理后台静态文件的 size / sha256；安装包可在下载后用 `sha256sum` 自行校验。发布说明正文来自 `docs/release/v2.0.1.md`。
