# 发布文档模板

> 用法：复制本文件为 `docs/release/v<版本号>.md`（例：`docs/release/v2.0.2.md`），
> 文件名必须与 tag 严格对应，否则 Actions 的 `verify` 会直接失败。
>
> **本文件正文会原样成为 GitHub Release 页的发布说明**，所以：
> - 面向使用者写（部署的人、装 App 的人），不是给自己看的开发笔记；
> - 不写内部路径、账号、密钥、服务器 IP；
> - 附件清单由流水线自动追加，不需要手写下载链接；
> - 必须写清每个产物的**支持架构**（Android / macOS 仅 arm64；服务端、Linux、Windows 桌面为 x64 + arm64）。

## 升级说明

写清楚升级的人要做什么，没有就写「无」。

- 数据库迁移：是否需要执行 `00NN_xxx.sql`，是否需要停机；
- 配置变更：新增了哪些环境变量 / Secret；
- 客户端：是否需要重新分发 APK / 桌面包 / 小程序；
- 兼容性：旧版本数据、旧客户端是否还能用。

## 已知问题

这一版明确没解决的问题，写清楚影响范围，别让使用者踩坑后才发现。没有就写「无」。

## 校验

部署包内的 `update-manifest.json` 记录 API、迁移工具与管理后台静态文件的 size / sha256；安装包可在下载后用 `sha256sum` 自行校验。
