# 宠栖 PatNest · 定位与导航服务配置指南（高德地图）

> 版本：V1.0 · 2026-11-03
> 适用范围：后端 server、微信小程序/H5（uniapp）、App（androidApp / 5+App）、管理后台（可选）
> 关联：`docs/09-主人端缺失接口清单.md` #8（距离排序/筛选）、`server/patnestServer/internal/config/config.go`

---

## 1 总览：谁用哪种 Key

高德开放平台一个应用下可以建多种类型的 Key，**类型用错会直接报 `USERKEY_PLAT_NOMATCH`**，对照关系如下：

| 端 | 用途 | Key 类型 | 配置位置 |
|---|---|---|---|
| 后端 server | 地理编码（地址→经纬度）、逆地理编码、POI 搜索、距离计算 | **Web服务** | `server/patnestServer/.env` 的 `AMAP_KEY`（已接入 config，禁止下发前端） |
| 微信小程序 | 定位（`wx.getLocation`） | 不需要高德 Key | 公众平台权限申请 + `manifest.json` |
| 微信小程序 | 地图展示 | 不需要高德 Key | 原生 `<map>` 组件（腾讯底图） |
| H5（uniapp 发布） | 地图展示 / 选点 | **Web端(JS API)** + 安全密钥 | uniapp H5 入口（见 §4） |
| App（uniapp 5+ 或 androidApp） | 定位/地图/导航 | **Android平台** | HBuilderX visual 界面或 `manifest.json` `sdkConfigs`（见 §5） |
| 管理后台（可选） | 创建机构时地图选点 | **Web端(JS API)** | `webadmin`（见 §6） |
| 各端 | 唤起高德 App 导航 | 无需 Key | `https://uri.amap.com/...` scheme（见 §7） |

核心原则：**Web服务 Key 只出现在后端**；客户端一律走定位权限、原生组件或跳转链接。

## 2 高德开放平台准备（一次性）

1. 注册开发者账号（个人主体可用），进入 https://console.amap.com/dev/key/app。
2. 创建应用"宠栖 PatNest"。控制台里的"应用类型"只是归类标签，不影响 Key 能不能用，选 **服务器** 或 **其他** 即可；真正决定 Key 用途的是下一步添加 Key 时选的"服务平台"。在下面分别添加 Key：
   - `AMAP_WEB_KEY`：服务平台选 **Web服务**（后端用）。
   - `AMAP_JS_KEY`：服务平台选 **JS API**（H5/后台用，同时生成"安全密钥 jscode"，需配代理或 `securityJsCode`）。
   - `AMAP_ANDROID_KEY`：服务平台选 **Android SDK**（仅 App 打包时用，需填打包包名 `team.wd.atnestapp` 与签名 SHA1）。
3. 个人认证账号免费配额：Web服务日配额十万级，毕设演示绰绰有余；上线前记得给 Key 配置 **IP 白名单**（后端机出口 IP）。

## 3 后端 server

### 3.1 已完成的接入

`config.Config` 已读取两个环境变量，本地与 Docker/systemd 部署的 `.env` 均已加占位：

```ini
# server/patnestServer/.env、deploy/docker/.env.example、/opt/patnest/api/shared/.env
AMAP_KEY=你的Web服务Key
AMAP_BASE_URL=https://restapi.amap.com
```

### 3.2 后端典型用法（地理编码）

机构保存地址时补全经纬度（成功结果写入 `sitters.latitude/longitude`，**只在新增或地址变更时调用一次**，避免重复消耗配额）：

```
GET {AMAP_BASE_URL}/v3/geocode/geo?address=呼和浩特市赛罕区大学东街&city=呼和浩特&key=AMAP_KEY&output=JSON
```

响应 `geocodes[0].location` 即 `经度,纬度`（GCJ-02 坐标系）。距离排序不需要调高德接口，在 `/sitters` 查询里用 SQL Haversine 直接算：

```sql
6371 * acos(cos(radians($me_lat)) * cos(radians(s.latitude))
           * cos(radians(s.longitude) - radians($me_lng))
           + sin(radians($me_lat)) * sin(radians(s.latitude))) AS distance_km
```

注意：库里存的坐标是高德 GCJ-02，微信 `wx.getLocation` 默认返回 `gcj02`，两边坐标系一致，可直接混用；Apple 平台是 WGS-84，跨端计算距离需要 `type: 'gcj02'`。

## 4 uniapp 微信小程序端（`uniapp/patnestUniapp`）

### 4.1 定位（用原生能力，不依赖高德 Key）

1. **微信公众平台**（mp.weixin.qq.com）→ 开发管理 → 接口设置：申请开通 **地理位置 `wx.getLocation`** 与 **位置展示 `wx.chooseLocation`/`wx.openLocation`**（需类目与场景说明，个人主体可用）。
2. `manifest.json` → `mp-weixin` 节点增加（当前工程还没有这两项）：

```json
"mp-weixin" : {
    "appid" : "你的小程序AppID",
    "permission" : {
        "scope.userLocation" : {
            "desc" : "用于在找机构时按距离排序并展示导航入口"
        }
    },
    "requiredPrivateInfos" : [ "getLocation", "chooseLocation", "openLocation" ]
}
```

3. 获取当前位置并传给后端：

```js
uni.getLocation({
  type: 'gcj02',
  success: (res) => {
    // 找机构：带上用户坐标
    api.listSitters({ latitude: res.latitude, longitude: res.longitude, sort: 'distance' })
  }
})
```

### 4.2 地图展示

小程序内的地图卡片用 uni-app 原生 `<map>` 组件（微信底层是腾讯底图，marker 直接用后端返回的 GCJ-02 坐标即可），不需要接高德 SDK。

## 5 uniapp App 端 / androidApp

uniapp 发行 App（5+ Runtime）时在 HBuilderX 可视化界面：**manifest.json → App模块配置 → 定位 → 选"高德定位"**，填入 Android Key；对应 JSON 位置：

```json
"app-plus": {
    "distribute": {
        "sdkConfigs": {
            "geolocation": {
                "amap": { "__platform__": ["android"], "appkey_ios": "", "appkey_android": "AMAP_ANDROID_KEY" }
            }
        }
    }
}
```

要点：Android Key 与**包名 + 签名 SHA1** 绑定，HBuilderX 云端打包与本地离线打包的 SHA1 不同，报 `INVALID_USER_SCODE` 优先核对这里（本项目证书见 §5.1）。若走 KMP `androidApp` 原生路线，则在高德官网下载定位/导航 SDK，`AndroidManifest.xml` 配 `com.amap.api.v2.apikey`。演示期最省事的方案是 App 端不集成 SDK，直接跳高德（见 §7）。

### 5.1 本项目签名证书与 SHA1 获取

证书已放在 `app/patnestApp/buildkeys/`，`androidApp/build.gradle.kts` 的 `signingConfigs` 已指向它们：

| 用途 | keystore | 别名 | store/key 密码 | SHA1（安全码） |
| --- | --- | --- | --- | --- |
| 调试版 | `patnestapp_debug.jks` | `key0` | `patnestapp_debug` | `B7:B5:39:10:5C:67:D9:9B:2E:22:3C:43:D4:ED:01:A1:E7:B4:E2:66` |
| 发布版 | `patnestapp_release.jks` | `key0` | `patnestapp_release` | `A9:CB:08:86:2D:B9:B5:EF:DE:F5:1C:8C:11:5B:99:CB:0C:33:7E:4F` |

以后换机器或重建证书时，自己查 SHA1：

```powershell
# 从 keystore 查（-alias 可省略，会列出全部条目）
keytool -list -v -keystore app\patnestApp\buildkeys\patnestapp_release.jks -storepass patnestapp_release -alias key0

# 从导出的证书文件查
keytool -printcert -file release.cer
```

```bash
# JDK 的 jarsigner 也能看 APK 实际用的是哪张证书（-certfile 显示摘要算法，不是 SHA1，需加 -printcert）
jarsigner -verify -verbose -certs app-release.apk | Select-String "Signer's Certificate"
```

拿到 APK 后核对签名（不需要重新构建）：

```powershell
# build-tools 下的 apksigner，路径随 SDK 版本变化
& "$env:LOCALAPPDATA\Android\Sdk\build-tools\35.0.0\apksigner.bat" verify --print-certs androidApp-release.apk
```

配置到高德控制台：一个 Android Key 可以同时填两个 SHA1，所以不用为 debug/release 建两张 Key。

1. 控制台 → 我的应用 → 添加 Key，**服务平台选 Android平台**。
2. 包名填 `team.wd.atnestapp`（必须与 `applicationId` 完全一致）。
3. 发布版安全码 SHA1 填上表发布版值；调试版安全码 SHA1 填上表调试版值。
4. 提交后，Android Studio 直接 Run（走 `debug` 变体）用 debug 证书，`assembleRelease` 用 release 证书，两张都能通过校验。

注意：密码目前明文写在 `androidApp/build.gradle.kts` 里，仓库若公开需改到 `local.properties`（`local.properties` 已被 `.gitignore` 忽略）或环境变量读取。`release` 变体此前没有指定 `signingConfig`，`assembleRelease` 会产出未签名 APK，现已指向发布证书。

## 6 H5 与管理后台（可选）

- **H5 端地图/选点**：引入 `@amap/amap-jsapi-loader`，用 JS API Key + 安全密钥：

```js
window._AMapSecurityConfig = { securityJsCode: 'AMAP_JS安全密钥' }
const AMap = await AMapLoader.load({ key: 'AMAP_JS_KEY', version: '2.0', plugins: ['AMap.Geolocation', 'AMap.PlaceSearch'] })
```

  生产环境建议把 `securityJsCode` 换成"代理转发"方式（官方文档：安全域名代理），前端域名需在 Key 控制台绑定白名单。
- **管理后台**：只有"创建/编辑机构时地图选点"需要，按需再接；纯看列表/统计不需要任何地图配置。
- **桌面端（KMP Desktop）**：演示范围不含地图，机构坐标在数据库里即可，不配置。

## 7 导航：唤起高德 App / 兜底

统一使用高德 URI 聚合链接，按端选择策略：

| 场景 | 做法 |
|---|---|
| 小程序 | 首选 `uni.openLocation({latitude, longitude, name, address})`（微信内置导航，可选高德/腾讯/App处理）；小程序内**无法直接跳外部 App**，如需高德导航可复制链接或引导用户打开 |
| H5 / App 内 WebView | `https://uri.amap.com/navigation?from={用户lng},{用户lat},我的位置&to={机构lng},{机构lat},{机构名}&mode=car&coordinate=gaode&callnative=1`（有高德 App 就唤起，没有落 H5） |
| 仅看位置 | `https://uri.amap.com/marker?position={lng},{lat}&name={机构名}&coordinate=gaode&callnative=1` |

注意事项：`name`、地址等参数必须 `encodeURIComponent`；`callnative=1` 表示优先唤起 App；坐标一律传 GCJ-02（后端库里存的就是）。

## 8 合规清单

1. 隐私政策补充"收集位置信息"条目及使用目的（小程序审核必查）。
2. `wx.getLocation` 类目申请时场景描述与实际功能一致（附近机构排序、到店导航）。
3. 后端地理编码结果落库缓存，不反复请求；Web服务 Key 设置 IP 白名单。
4. 用户关闭定位权限时功能降级（按价格/评分排序照常可用），不要阻塞主流程。

## 9 常见问题速查

| 错误码/现象 | 原因 | 处理 |
|---|---|---|
| `USERKEY_PLAT_NOMATCH` | Key 类型与调用方式不符 | 对照 §1 表重新建对应类型 Key |
| `INVALID_USER_SCODE` | Android Key 的包名/SHA1 不匹配 | 核对实际打包签名 SHA1（云打包≠本地调试） |
| `DAILY_QUERY_OVER_LIMIT` | 日配额耗尽 | 地理编码结果缓存、上线提额 |
| 小程序 `getLocation fail auth deny` | 未申请接口或未声明 | §4.1 的公众平台开通 + `requiredPrivateInfos` |
| H5 地图空白/报安全密钥 | `securityJsCode` 缺失或域名未绑定 | §6 配置密钥与域名白名单 |
| 导航落点偏移 | 坐标系混用（WGS-84 vs GCJ-02） | 全链路统一 GCJ-02，Apple 端 `getLocation` 指定 `gcj02` |
