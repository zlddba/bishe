# 宠栖 PatNest · 定位与导航服务配置指南（高德地图）

> 版本：V1.1 · 2026-11-03
> 适用范围：后端 server、微信小程序（uniapp）、App 三端（KMP：Android / iOS / Desktop）、管理后台（webadmin）
> 端归属约定：`uniapp/patnestUniapp` **只发行微信小程序**；App 形态全部由 `app/patnestApp` 承担，uniapp 不再出 5+App，也不出 H5。
> 关联：`docs/09-主人端缺失接口清单.md` #8（距离排序/筛选）、`server/patnestServer/internal/config/config.go`

---

## 1 总览：谁用哪种 Key

高德开放平台一个应用下可以建多种类型的 Key，**类型用错会直接报 `USERKEY_PLAT_NOMATCH`**，对照关系如下：

| 端 | 用途 | Key 类型 | 配置位置 |
|---|---|---|---|
| 后端 server | 地理编码（地址→经纬度）、逆地理编码、POI 搜索、距离计算 | **Web服务** | `server/patnestServer/.env` 的 `AMAP_KEY`（已接入 config，禁止下发前端） |
| 微信小程序 | 定位（`wx.getLocation`） | 不需要高德 Key | 公众平台权限申请 + `manifest.json` |
| 微信小程序 | 地图展示 | 不需要高德 Key | 原生 `<map>` 组件（腾讯底图） |
| App-Android（KMP `androidApp`） | 定位 / 地图 / 导航 | **Android平台**（包名 + 签名 SHA1） | `AndroidManifest.xml` meta-data + Gradle 依赖（见 §5.1、§5.2） |
| App-iOS（KMP `iosApp`） | 定位 / 地图 / 导航 | **iOS平台**（Bundle ID） | CocoaPods 集成高德 SDK + `Info.plist`（见 §5.3） |
| App-Desktop（KMP `desktopApp`） | 无 GPS；地址解析坐标 + 应用内地图选点弹框 | **Web服务**（地址解析、逆地理、静态地图）+ **JS API**（浏览器选点页，备用） | 全部由后端代理，密钥不进桌面客户端（见 §5.4） |
| 管理后台（webadmin） | 创建/编辑机构时地图选点 | **Web端(JS API)** + 安全密钥 | `VITE_AMAP_JS_KEY`（见 §6，已接入） |
| 各端 | 唤起高德 App 导航 | 无需 Key | `https://uri.amap.com/...` scheme（见 §7） |

核心原则：**Web服务 Key 只出现在后端**；客户端一律走定位权限、原生组件或跳转链接。

## 2 高德开放平台准备（一次性）

1. 注册开发者账号（个人主体可用），进入 https://console.amap.com/dev/key/app。
2. 创建应用"宠栖 PatNest"。控制台里的"应用类型"只是归类标签，不影响 Key 能不能用，选 **服务器** 或 **其他** 即可；真正决定 Key 用途的是下一步添加 Key 时选的"服务平台"。在下面分别添加 Key：
   - `AMAP_WEB_KEY`：服务平台选 **Web服务**（后端用）。
   - `AMAP_JS_KEY`：服务平台选 **JS API**（管理后台地图选点、以及桌面端选点页都用它，同时生成"安全密钥 jscode"，需配代理或 `securityJsCode`）。
     两处读取方式不同：后台是构建期 `VITE_AMAP_JS_KEY`，后端是运行期 `AMAP_JS_KEY` + `AMAP_JS_SECURITY_CODE`（桌面端选点页由后端渲染）。
   - `AMAP_ANDROID_KEY`：服务平台选 **Android 平台**（KMP `androidApp` 用，需填包名 `team.wd.atnestapp` 与两张签名的 SHA1，见 §5.2）。
   - `AMAP_IOS_KEY`：服务平台选 **iOS 平台**（KMP `iosApp` 用，需填 Bundle ID；注意工程里带 `$(TEAM_ID)` 后缀，要填 Xcode 解析后的完整值，见 §5.3）。
3. 个人认证账号免费配额：Web服务日配额十万级，毕设演示绰绰有余；上线前记得给 Key 配置 **IP 白名单**（后端机出口 IP）。

## 3 后端 server

### 3.1 已完成的接入

`config.Config` 已读取两个环境变量，本地与 Docker/systemd 部署的 `.env` 均已加占位：

```ini
# server/patnestServer/.env、deploy/docker/.env.example、/opt/patnest/api/shared/.env
AMAP_KEY=你的Web服务Key
AMAP_BASE_URL=https://restapi.amap.com
```

### 3.2 后端典型用法（地理编码）

机构保存地址时补全经纬度（成功结果写入 `sitters.latitude/longitude`，**只在新增或地址变更时调用一次**，避免重复消耗配额）：

```
GET {AMAP_BASE_URL}/v3/geocode/geo?address=呼和浩特市赛罕区大学东街&city=呼和浩特&key=AMAP_KEY&output=JSON
```

响应 `geocodes[0].location` 即 `经度,纬度`（GCJ-02 坐标系）。距离排序不需要调高德接口，在 `/sitters` 查询里用 SQL Haversine 直接算：

```sql
6371 * acos(cos(radians($me_lat)) * cos(radians(s.latitude))
           * cos(radians(s.longitude) - radians($me_lng))
           + sin(radians($me_lat)) * sin(radians(s.latitude))) AS distance_km
```

注意坐标系：库里存的机构坐标是高德 **GCJ-02**。`uni.getLocation` 的 `type` 缺省是 `wgs84`，
必须显式写 `type: 'gcj02'` 才和机构坐标同一基准；iOS CoreLocation 拿到的也是 WGS-84，
同样要先转成 GCJ-02 再传后端（见 §5.3）。两者混用会产生几十到几百米的偏移。

## 4 uniapp 微信小程序端（`uniapp/patnestUniapp`）

uniapp 工程只用于微信小程序，因此这里只涉及微信自身的定位与地图能力，**不需要任何高德 Key**；
`manifest.json` 里不用配 `app-plus.sdkConfigs`（App 走 §5）和 `h5`（本项目不产 H5）。

### 4.1 定位（用原生能力，不依赖高德 Key）

1. **微信公众平台**（mp.weixin.qq.com）→ 开发管理 → 接口设置：申请开通 **获取地理位置 `wx.getLocation`** 与 **选择位置 `wx.chooseLocation`**（需填类目与场景说明，个人主体可用）。
   `wx.openLocation` 只是打开一个已知坐标做展示，不取用户位置，**不需要申请，也不要写进 `requiredPrivateInfos`**（写了会被判非法接口名）。
2. `uniapp/patnestUniapp/manifest.json` 的 `mp-weixin` 节点已补好权限声明，只剩把 `appid` 换成真实小程序 AppID：

```json
"mp-weixin" : {
    "appid" : "你的小程序AppID",
    "permission" : {
        "scope.userLocation" : {
            "desc" : "用于在找机构时按距离排序并展示到店导航入口"
        }
    },
    "requiredPrivateInfos" : [ "getLocation", "chooseLocation" ]
}
```

3. 获取当前位置并传给后端：

```js
uni.getLocation({
  type: 'gcj02',
  success: (res) => {
    // 找机构：带上用户坐标
    api.listSitters({ latitude: res.latitude, longitude: res.longitude, sort: 'distance' })
  }
})
```

### 4.2 地图展示

小程序内的地图卡片用 uni-app 原生 `<map>` 组件（微信底层是腾讯底图，marker 直接用后端返回的 GCJ-02 坐标即可），不需要接高德 SDK。

## 5 KMP App 端（Android / iOS / Desktop）

App 三端都在 `app/patnestApp`：`androidApp`、`iosApp`、`desktopApp` 共用 `shared`。
三端能力差别很大，建议照工程里已有的 expect/actual 套路（`shared/src/commonMain/.../Platform.kt`、
`data/api/HttpClientEngine.kt`）抽一层定位能力，UI 层只认一个接口：

```kotlin
// commonMain：坐标一律 GCJ-02；拿不到就返回 null，调用方降级为"不显示距离"
data class Coords(val latitude: Double, val longitude: Double)

interface DeviceLocation {
    suspend fun current(): Coords?
}

// 和 HttpClientEngine.kt 一样用 expect/actual 工厂，各端在 androidMain / iosMain / jvmMain 里 actual
expect fun createDeviceLocation(): DeviceLocation
```

| 端 | 定位来源 | 坐标系 | 地图/导航 |
|---|---|---|---|
| `androidApp` | 高德定位 SDK，或系统 `FusedLocationProvider` | 高德 SDK 直接给 GCJ-02；系统给 WGS-84 需转换 | 唤起高德 App（§7）为主 |
| `iosApp` | CoreLocation 或高德 iOS SDK | CoreLocation 是 WGS-84，**必须转 GCJ-02** | `iosamap://` 唤起（§7） |
| `desktopApp` | 无 GPS，只有 IP 定位 / 手动选城市 | 后端返回什么就是什么 | 浏览器打开 `uri.amap.com`（§5.4） |

### 5.1 Android（androidApp）

`androidApp/src/main/AndroidManifest.xml` 目前没有任何权限声明，接入定位时要加：

```xml
<uses-permission android:name="android.permission.ACCESS_FINE_LOCATION" />
<uses-permission android:name="android.permission.ACCESS_COARSE_LOCATION" />

<application ...>
    <!-- Key 从 local.properties / 环境变量注入，别把密钥提交进仓库 -->
    <meta-data
        android:name="com.amap.api.v2.apikey"
        android:value="${amapKey}" />
</application>
```

`androidApp/build.gradle.kts` 里补 placeholder 和依赖（工程已配 `mavenCentral()`，高德 SDK 就发在上面；
具体版本以高德下载页/mvnrepository 为准）：

```kotlin
// local.properties 已被 app/patnestApp/.gitignore 忽略，和证书密码放一起最合适
val localProps = java.util.Properties().apply {
    val f = rootProject.file("local.properties")
    if (f.exists()) f.inputStream().use { load(it) }
}

android {
    defaultConfig {
        manifestPlaceholders["amapKey"] =
            localProps.getProperty("AMAP_ANDROID_KEY") ?: System.getenv("AMAP_ANDROID_KEY") ?: ""
    }
}

dependencies {
    implementation("com.amap.api:location:<最新版本>")   // 只要定位
    // 地图/导航按需再引，体积明显变大，毕设演示建议不引：
    // implementation("com.amap.api:3dmap-location-search:<最新版本>")
    // implementation("com.amap.api:navi-3dmap-location-search:<最新版本>")
}
```

要点：

1. Android Key 与**包名 + 签名 SHA1**绑定，debug 和 release 两张证书的 SHA1 都要填进同一张 Key，
   否则 Android Studio 直接 Run 出来的包会报 `INVALID_USER_SCODE`（取法见 §5.2）。
2. `compileSdk` 是 37、`minSdk` 28，高于高德 SDK 要求，无需为它降级；若某个 SDK 版本合并 manifest
   报错，先升 SDK 版本而不是动 `compileSdk`。
3. 运行时权限用工程已有的 `androidx.activity:activity-compose`：
   `rememberLauncherForActivityResult(ActivityResultContracts.RequestPermission())`，
   用户拒绝就照常按价格/评分排序，不阻塞主流程。
4. 现在 `release` 的 `isMinifyEnabled = false`；将来开混淆时要按高德文档补 keep 规则，否则定位回调会静默失效。
5. 演示期最省事的方案：不集成任何高德 SDK，App 里只填地址 + "去这里"跳高德（§7），一行权限都不用申请。

### 5.2 Android 签名证书与 SHA1 获取

证书已放在 `app/patnestApp/buildkeys/`，`androidApp/build.gradle.kts` 的 `signingConfigs` 已指向它们：

| 用途 | keystore | 别名 | store/key 密码 | SHA1（安全码） |
| --- | --- | --- | --- | --- |
| 调试版 | `patnestapp_debug.jks` | `key0` | `patnestapp_debug` | `B7:B5:39:10:5C:67:D9:9B:2E:22:3C:43:D4:ED:01:A1:E7:B4:E2:66` |
| 发布版 | `patnestapp_release.jks` | `key0` | `patnestapp_release` | `A9:CB:08:86:2D:B9:B5:EF:DE:F5:1C:8C:11:5B:99:CB:0C:33:7E:4F` |

以后换机器或重建证书时，自己查 SHA1：

```powershell
# 从 keystore 查（-alias 可省略，会列出全部条目）
keytool -list -v -keystore app\patnestApp\buildkeys\patnestapp_release.jks -storepass patnestapp_release -alias key0

# 从导出的证书文件查
keytool -printcert -file release.cer
```

```bash
# JDK 的 jarsigner 也能看 APK 实际用的是哪张证书（-certfile 显示摘要算法，不是 SHA1，需加 -printcert）
jarsigner -verify -verbose -certs app-release.apk | Select-String "Signer's Certificate"
```

拿到 APK 后核对签名（不需要重新构建）：

```powershell
# build-tools 下的 apksigner，路径随 SDK 版本变化
& "$env:LOCALAPPDATA\Android\Sdk\build-tools\35.0.0\apksigner.bat" verify --print-certs androidApp-release.apk
```

配置到高德控制台：一个 Android Key 可以同时填两个 SHA1，所以不用为 debug/release 建两张 Key。

1. 控制台 → 我的应用 → 添加 Key，**服务平台选 Android平台**。
2. 包名填 `team.wd.atnestapp`（必须与 `applicationId` 完全一致）。
3. 发布版安全码 SHA1 填上表发布版值；调试版安全码 SHA1 填上表调试版值。
4. 提交后，Android Studio 直接 Run（走 `debug` 变体）用 debug 证书，`assembleRelease` 用 release 证书，两张都能通过校验。

注意：密码目前明文写在 `androidApp/build.gradle.kts` 里，仓库若公开需改到 `local.properties`（`local.properties` 已被 `.gitignore` 忽略）或环境变量读取。`release` 变体此前没有指定 `signingConfig`，`assembleRelease` 会产出未签名 APK，现已指向发布证书。

### 5.3 iOS（iosApp）

iOS 走 Xcode 工程，高德 SDK 不参与 Gradle 构建，所以配置分两处。

1. **Bundle ID 要和 Key 对得上。** `iosApp/Configuration/Config.xcconfig` 里写的是
   `team.wd.atnestapp.PatnestApp$(TEAM_ID)`，`TEAM_ID` 填了之后最终包名会带后缀，
   控制台**必须填 Xcode Build Settings 里解析出来的那个完整值**，否则鉴权一直失败。
   这张 Key 的服务平台选 **iOS 平台**。
2. **`iosApp/iosApp/Info.plist` 补权限文案**（当前文件里只有版本号那几个键）：

```xml
<key>NSLocationWhenInUseUsageDescription</key>
<string>用于在找机构时按距离排序并展示到店导航入口</string>

<!-- 跳过高德 App 前需要 canOpenURL，必须声明 scheme -->
<key>LSApplicationQueriesSchemes</key>
<array>
    <string>iosamap</string>
</array>
```

3. **定位实现二选一：**
   - 只用系统能力（推荐，毕设够用）：Swift 层用 CoreLocation 拿坐标，经 `shared` 的
     `iosMain` actual 回传给 Compose。注意 CoreLocation 返回 **WGS-84**，
     要转成 GCJ-02 再发给后端，否则距离和导航都会偏。
   - 用高德 iOS SDK：官方以 CocoaPods 发布（`pod 'AMapLocation'` 等），当前工程没有 Podfile，
     需要先 `pod init` 再集成；SDK 直接返回 GCJ-02，省掉坐标转换，代价是多一套构建链。
4. **导航**不装高德 SDK 也能做：拼 `iosamap://path?sourceApplication=PatNest&dlat={纬度}&dlon={经度}&dname={机构名}&dev=0&t=0`
   用 `UIApplication.open` 唤起，`dev=0` 表示坐标已是 GCJ-02；没装高德 App 就回落网页版（§7）。

### 5.4 Desktop（desktopApp）

桌面端没有 GPS，也**绝对不能把 `AMAP_KEY`（Web服务 Key）放进客户端**——那是后端专用密钥（§1 核心原则）。按需要程度三档：

| 方案 | 做法 | 成本 |
|---|---|---|
| 不做距离 | 只按价格/评分/容量排序，现有接口已支持 | 0，主人端浏览列表的默认降级态 |
| **地址解析坐标（已实现）** | 桌面端"机构资料"填城市 + 地址 → 后端地理编码补 GCJ-02 坐标 | 见下 |
| **地图选点弹框（已实现）** | 桌面端"地图查看 / 选点"→ 应用内弹框，瓦片连续底图 + 红点选点 + 逆地理回填地址 | 见下 |
| 浏览器选点页（备用） | 桌面端"用浏览器选点"→ 一次性选点页（完整交互地图，带 POI 搜索/多级缩放）→ 轮询取回坐标 | 见下 |
| 城市级定位（未做） | 后端调高德 IP 定位 `GET {AMAP_BASE_URL}/v3/ip?key=AMAP_KEY`，只用来定默认城市 | 需再加一个接口 |

说明：Compose Desktop 没有内嵌浏览器，为一张选点页引入 JCEF 这类原生浏览器依赖不划算
（runtime 上百 MB 且分平台、heavyweight 组件还会盖在 Compose 弹框之上），
所以主路径做成**应用内弹框 + 瓦片自绘**：拖动全程本地渲染，只在松手后补新露出的瓦片，
因此手感是连续的，也不会每帧打一次接口。投影换算集中在 `ui/util/MapProjection.kt`
（Web Mercator，`world = 256 * 2^zoom`），红点始终指向选中的位置。
需要完整交互地图（POI 检索、更细层级）时用备用的浏览器选点页。两条路径都不把任何 Key 交给桌面客户端。

已实现的地址解析链路：

1. 后端 `POST /api/v1/geo/geocode`（`handler/geo_code.go` + `internal/amap/geocode.go`）：
   入参 `{address, city}`，转发高德 `v3/geocode/geo`，返回
   `latitude / longitude / formatted_address / resolved_city / district / adcode / level / from_cache`。
   Key 只在后端，响应里不含任何密钥；未配 `AMAP_KEY` 时返回 501 并给出可操作提示。
2. 结果落 `geocode_cache` 表（迁移 `0011`），按 `md5(city|地址归一化)` 做键，半年内同一地址不再重复打配额；
   同时用 Redis 给每个账号做每分钟 20 次的限流（Redis 未启用时跳过，本地开发不受影响）。
3. 桌面端 `机构资料`页（`SitterProfilePage.kt`）：**不再手填经纬度**，坐标只有两个来源——
   "按地址解析坐标"（城市 + 地址 → 后端地理编码）和"地图查看 / 选点"（应用内弹框）。
   页面下方一行状态文字实时说明当前坐标及其来源（地址解析 / 地图选点 / 服务端已有），
   地址被改过但坐标还是旧的那次解析结果时用警告色提示"地址已修改，建议重新解析坐标"。
   坐标只在点"保存资料"后随 `PUT /sitter/shop/me` 落库；两个值不全时按"不改动已存坐标"处理。
4. 查看位置也在同一个弹框里完成（打开就是当前坐标的地图），弹框底部另有"在浏览器打开高德"
   入口，走 `https://uri.amap.com/marker?position={lng},{lat}&coordinate=gaode&callnative=1`
   （`ui/util/AmapWeb.kt`），不嵌 SDK、不需要 Key，用于对着真实 POI 再核一眼。

已实现的地图选点链路：

主路径（应用内弹框）：

1. `GET /api/v1/geo/tile?z=&x=&y=`：后端代理 256×256 瓦片（四个 CDN 轮询），返回 PNG。
   瓦片内容不随用户变化，所以带 `Cache-Control: public, max-age=86400`，
   服务端另有进程内 LRU（24 小时、24MB 上限）和每账号每分钟 600 次的限流。
   注意：`webrd0x.is.autonavi.com` 是高德网页版在用的公开瓦片，不吃 Web服务 Key 的配额，
   但开放平台协议里并没有明确授权第三方直接调用 —— **只适合毕设演示**。
   正式对外时把 `internal/amap/tile.go` 里的地址换成官方授权来源即可，客户端的瓦片网格逻辑不用改。
2. `GET /api/v1/geo/static-map?latitude=&longitude=&zoom=&width=&height=`：后端代理高德
   `v3/staticmap`，以该点为中心返回整张 PNG。这是**兜底路径**：瓦片一条都没拉到时
   （CDN 被拦、后端没出包）弹框自动改用它。同样按"坐标量化 + 缩放 + 尺寸"做 LRU（10 分钟），
   每账号每分钟 120 次；未配 `AMAP_KEY` 时返回 501。
2. `POST /api/v1/geo/reverse`：坐标 → 地址文本，结果与地理编码共用 `geocode_cache`
   表（缓存键用 `regeo|` 前缀区分方向，省掉一次迁移），30 天内同一坐标不重复请求。
3. 桌面端 `MapPickerPanel`：拖动地图（本地平移，松手补瓦片）、`-/+` 调缩放层级（3~18），
   或先输入城市 + 地址"移到该地址"跳到目标位置；底部实时显示选中坐标与逆地理地址，
   点"确定选点"写回机构资料（仍需点"保存资料"才落库）。

备用路径（浏览器选点页）：

1. 桌面端 `POST /api/v1/geo/pick`（携带当前坐标与机构名）→ 后端生成 16 字节随机令牌，
   库里只存 `sha256(令牌)`，返回相对路径 `path`；桌面端用自己的 `apiBase` 拼成完整链接后用系统浏览器打开。
2. 浏览器里的选点页由后端渲染（`handler/geo_picker.go` + `handler/geo_picker_page.go`），
   加载高德 JS API，支持搜索、点击落点、拖动标记、逆地理回填地址；点"确认选点"即 `POST /api/v1/geo/pick/:token` 回写坐标。
3. 桌面端每 800ms 轮询 `GET /api/v1/geo/pick-result/:token`，`done` 时后端顺手删掉会话（取走即销毁），
   `expired` 或轮询到超时都会给出可操作提示，用户可以直接改用"按地址解析坐标"。
4. 会话 5 分钟过期、只有创建者能取走、每账号每分钟最多发起 6 次；页面与后端同源，不额外开端口。
   前提是 `AMAP_JS_KEY` 已在后端配置，且该 Key 的域名白名单放行后端对外访问地址（留空表示不限制）。
   一点要知道的取舍：令牌出现在选点页 URL 里，会被 Nginx `access_log` 记一条。它 5 分钟过期、只能交回一次坐标、
   也只能由创建者取走，所以泄露面很小；如果答辩后要认真对外，可把令牌换成 POST 提交或给日志加脱敏。

## 6 管理后台（webadmin）

后台是本项目里唯一需要在浏览器里加载高德 JS API 的地方，机构管理的地图选点已经接入（§6.1）。
uniapp 只产微信小程序、不再产 H5，所以除后台外没有别的 Web 端地图；将来若真要做独立 H5，
直接复用后台这套 JS API Key 与按需注入脚本的写法即可，不必引入 `@amap/amap-jsapi-loader`。

### 6.1 管理后台机构地图选点（已实现）

配置项只有两个，写在 `webadmin/patnestServerAdminWeb/.env.local`（模板见同目录 `.env.example`，
该文件已被 `.gitignore` 忽略）：

```bash
VITE_AMAP_JS_KEY=你的JS-API-Key
VITE_AMAP_SECURITY_CODE=配套的jscode安全密钥
```

| 文件 | 作用 |
| --- | --- |
| `src/composables/useAmap.js` | 按需注入高德 JS API 脚本（首次打开地图才加载），并注册 `AutoComplete`/`Geocoder` 插件 |
| `src/components/MapPickerDialog.vue` | 选点弹窗：关键词搜索、点击落点、拖动标记、逆地理回填地址 |
| `src/views/SittersView.vue` | 经纬度行新增"地图选点"按钮；坐标有效时可"在高德地图中查看"；详情抽屉同样带查看链接 |

行为约定：

1. 选点结果写入表单的 `latitude` / `longitude`（GCJ-02，六位小数），保存时走原有的
   `POST /admin/sitters`、`PUT /admin/sitters/:id`，后端无需改动。
2. 地址文本只在"表单原本为空"或"上一次是地图写入的"时才被逆地理结果覆盖，
   管理员手打过的地址不会被冲掉。
3. 未配置 Key 时弹窗显示提示文案而不是白屏，仍可手工填经纬度；Key 用错类型会直接显示
   高德返回的错误码，按 §1 的表换成 JS API Key。
4. "在高德地图中查看"走 `https://uri.amap.com/marker`，不依赖 Key，也不会把前端密钥暴露在链接里。

配额与安全：JS API 的地图瓦片、逆地理编码都计入该 Key 的日配额，选点属于低频后台操作，
个人认证额度足够；正式环境建议给 Key 绑定后台域名白名单，并按高德文档把 `securityJsCode`
换成代理转发方式。

## 7 导航：唤起高德 App / 兜底

本项目四端各自的推荐做法，优先系统/官方入口，其次 URI 聚合链接，最后才是复制地址：

| 场景 | 做法 |
|---|---|
| 微信小程序（uniapp） | 首选 `uni.openLocation({latitude, longitude, name, address})`，微信自己处理地图与导航选择；小程序内**无法直接跳外部 App**，需要高德就让用户复制地址 |
| Android（KMP `androidApp`） | 先试 scheme `androidamap://viewMap?sourceApplication=PatNest&poiname={机构名}&lat={纬度}&lon={经度}&dev=0`，用 `PackageManager` 判断是否装了高德；没装就 `Intent.ACTION_VIEW` 打开 `https://uri.amap.com/navigation?...&callnative=1` |
| iOS（KMP `iosApp`） | 先试 `iosamap://path?sourceApplication=PatNest&dlat=&dlon=&dname=&dev=0&t=0`，前提是 `Info.plist` 里声明了 `LSApplicationQueriesSchemes`（见 §5.3，当前工程还没加）；没装高德 App 则 `UIApplication.open` 打开网页版 |
| Desktop（KMP `desktopApp`） | `java.awt.Desktop.browse` 打开 `https://uri.amap.com/marker?position={lng},{lat}&name={机构名}`；要手机导航就展示同一链接的二维码 |
| 管理后台（webadmin） | 直接 `window.open('https://uri.amap.com/marker?...')`，已接入（见 §6.1） |
| 仅看位置（通用兜底） | `https://uri.amap.com/marker?position={lng},{lat}&name={机构名}&coordinate=gaode&callnative=1` |

注意事项：`name`、地址等参数必须 `encodeURIComponent`；`dev=0` / `coordinate=gaode` 表示传的是 GCJ-02（后端库里存的就是），
不要传成 WGS-84；`callnative=1` 表示优先唤起 App。

## 8 合规清单

1. 隐私政策补充"收集位置信息"条目及使用目的（小程序审核必查）。
2. `wx.getLocation` 类目申请时场景描述与实际功能一致（附近机构排序、到店导航）。
3. 后端地理编码结果落库缓存，不反复请求；Web服务 Key 设置 IP 白名单。
4. 用户关闭定位权限时功能降级（按价格/评分排序照常可用），不要阻塞主流程。
5. Android 12+ 要区分"精确/近似"位置权限：只申请 `ACCESS_COARSE_LOCATION` 时距离排序会明显不准，
   申请 `ACCESS_FINE_LOCATION` 需在隐私政策里写明用途；后台定位（`ACCESS_BACKGROUND_LOCATION`）本项目不要申请。
6. iOS 上架要填 App 隐私"位置信息"用途，且与 `Info.plist` 的 `NSLocationWhenInUseUsageDescription` 文案一致。

## 9 常见问题速查

| 错误码/现象 | 原因 | 处理 |
|---|---|---|
| `USERKEY_PLAT_NOMATCH` | Key 类型与调用方式不符 | 对照 §1 表重新建对应类型 Key |
| `INVALID_USER_SCODE` | Android/iOS Key 的包名（Bundle ID）与签名对不上 | Android：核对 debug 与 release 两张证书的 SHA1 是否都填了（§5.2）；iOS：核对 `Config.xcconfig` 解析后的完整 Bundle ID（§5.3） |
| `DAILY_QUERY_OVER_LIMIT` | 日配额耗尽 | 地理编码结果缓存、上线提额 |
| 小程序 `getLocation fail auth deny` | 未申请接口或未声明 | §4.1 的公众平台开通 + `requiredPrivateInfos` |
| 后台地图空白/报安全密钥 | `VITE_AMAP_JS_KEY` 没配、`securityJsCode` 缺失或域名未绑定 | §6.1 配 Key 与域名白名单；未配 Key 时弹窗会显示提示而不是白屏 |
| 导航落点偏移 | 坐标系混用（WGS-84 vs GCJ-02） | 全链路统一 GCJ-02：小程序 `uni.getLocation` 显式 `type: 'gcj02'`，iOS CoreLocation 结果先转换，Android 用高德 SDK 则已是 GCJ-02 |
| iOS 定位一直不回调 | `Info.plist` 缺 `NSLocationWhenInUseUsageDescription`，或没调用 `requestWhenInUseAuthorization()` | §5.3 第 2 步 |
| 桌面端拿不到位置 | 桌面机通常没有 GPS | 属预期，按 §5.4 用地址解析或地图选点补坐标；浏览列表则降级为按价格/评分排序 |
| 桌面端"在地图中选点"提示不可用 | 后端没配 `AMAP_JS_KEY`（创建会话返回 501） | §5.4 地图选点链路，或先用"按地址解析坐标" |
| 选点页打开是白屏/报安全密钥 | JS Key 与 `securityJsCode` 不匹配，或域名白名单没放行后端访问地址 | 控制台核对 Key 类型与白名单，见 §2 |
