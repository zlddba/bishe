# 宠栖 PatNest · 手机号注册与登录调整（2026-11-05）

> 需求：**注册必须填手机号；登录可以用「用户名」或「手机号」；没绑手机号的账号登录后要提示「请绑定手机号」。**
> 本次只改后端（`server/patnestServer`），客户端按下面第三节的字段接一下即可。

---

## 一、行为变化

| 项 | 改动前 | 改动后 |
|---|---|---|
| `POST /auth/register` 的 `phone` | 可选（空则账号没有手机号） | **必填**。缺失/空白 → `400 请填写手机号`；格式不对 → `400 请输入正确的 11 位手机号`；已被占用 → `409 该手机号已被注册` |
| 注册用户名 | 任意 3~50 字符 | 额外要求**不能是手机号格式**（否则和手机号登录撞车）→ `400 账号不能使用手机号格式，请换一个用户名` |
| `POST /auth/login` 的 `username` | 只按用户名查 | **用户名或手机号**都可以；两者若命中不同账号，优先用户名精确匹配 |
| 未绑手机号的账号登录 | 无任何提示 | 登录**仍然成功**，响应带 `need_bind_phone: true`、`user.phone_bound: false`，客户端据此弹窗 |

> 为什么允许未绑手机号的账号继续登录：这些是历史/后台导入账号，直接拒绝登录会把它们锁死在门外；
> 需求要的是「提示去绑定」，所以做成软提示 + 显式字段。

## 二、接口契约（前端需要的就两点）

**登录成功响应**（注册响应同结构）：

```json
{
  "code": 0,
  "message": "ok",
  "data": {
    "user": {
      "id": 36,
      "username": "zlddba",
      "nickname": "林点点",
      "role": "owner",
      "phone": "19839594411",
      "phone_bound": true
    },
    "access_token": "...",
    "refresh_token": "...",
    "expires_in": 1800,
    "need_bind_phone": false
  }
}
```

未绑定手机号时：`user.phone` 为空、`user.phone_bound = false`、`need_bind_phone = true`。

**绑定手机号**复用现有接口，不需要新路由：

```http
PUT /api/v1/auth/profile
Authorization: Bearer <token>
Content-Type: application/json

{ "phone": "13800001111" }
```

绑定后 `GET /api/v1/auth/me` 的 `phone` / `phone_bound` 会同步更新。

## 三、客户端要补的一步（前端）

两端目前登录后都是直接 toast「登录成功，欢迎 X」，没有读这两个字段，所以**弹窗还没出现**：

- 桌面端 `AppRoot.applyAuth()`：`me.phone.isNullOrBlank()` 时弹 `ModalKind.Confirm("请绑定手机号", ...)`，确认后 `go(AppPage.Profile)`
- 安卓端 `MobileState.applyAuth()`：同样条件 `sheet = MobileSheet.Message("请绑定手机号", ..., "去绑定") { go(MobileScreen.Profile) }`

后端已把这套判断需要的字段全部下发，客户端只需读 `need_bind_phone`（或 `user.phone`）一行判断。
